# pdfnative v1.4.0

<!-- GitHub Release title: v1.4.0 — Document outline/bookmarks, page labels, streamToFile, page-tree manipulation (merge/split/extract), COLRv1 advanced compositing -->

Delivers the **complete v1.4.0 roadmap** — document outline / bookmarks,
page labels, and a `streamToFile()` Node helper — plus two items pulled
forward: a **page-tree manipulation API** (`mergePdfs` / `splitPdf` /
`extractPages`) that unblocks `pdfnative-mcp`'s long-blocked `merge_pdfs` and
`split_pdf` tools, and **COLRv1 advanced compositing** (sweep gradients +
`PaintComposite` blend modes). 100% backward-compatible — every new feature is
additive or opt-in, and pre-existing PDFs are byte-identical for unchanged
code paths.

> _Still zero runtime dependencies. 77 test files / 2090 tests, all green._

## Highlights

- **feat(core): Document outline / bookmarks (`/Outlines`).** `DocumentParams.outline`
  accepts an explicit nested `OutlineItem[]` — each item carries a `title`,
  0-based `pageIndex`, optional `y`, `bold` / `italic` flags (`/F`), `color`
  (`/C`), and an `open` flag — or the literal `'auto'`, which derives a tree from
  the document's heading blocks, nested by level (H1 → H2 → H3). Setting
  `open: false` renders a branch **collapsed** with a spec-correct negative
  `/Count` (ISO 32000-1 §12.3.3); a collapsed node hides its descendants from
  ancestors' visible counts. The catalog gains `/Outlines` and
  `/PageMode /UseOutlines`. Bookmarks are purely navigational and PDF/A-safe.
  New `src/core/pdf-outline.ts`; `OutlineItem` exported from the
  root. ([src/core/pdf-outline.ts](../src/core/pdf-outline.ts))
- **feat(core): Page labels (`/PageLabels`).** `DocumentParams.pageLabels`
  (`PageLabelRange[]`) builds the `/PageLabels` number tree so viewers show
  roman-numeral front matter, decimal bodies, and prefixed appendices
  (`A-1, A-2…`). Styles: `decimal` / `roman` / `Roman` / `alpha` / `Alpha` /
  `none`, with `prefix` and `start`. Inline (no extra objects), PDF/A-safe. New
  `src/core/pdf-page-labels.ts`; `PageLabelRange` / `PageLabelStyle` exported.
  ([src/core/pdf-page-labels.ts](../src/core/pdf-page-labels.ts))
- **feat(stream): `streamToFile()` Node helper.** Pipes any streaming builder
  (`buildPDFStreamTrue` / `buildDocumentPDFStreamTrue` / `streamPdf`) directly
  to a file in **constant memory**, honouring write back-pressure (awaits
  `'drain'`) and an optional `AbortSignal`. On abort or any write error it
  releases the file descriptor and removes the partially-written file
  (best-effort), so a cancelled run never leaves an orphaned half-written PDF.
  `node:fs` is loaded via a dynamic + type-only import, so the browser bundle
  stays clean and tree-shakeable. Returns `{ bytesWritten, path }`.
  ([src/core/pdf-stream-writer.ts](../src/core/pdf-stream-writer.ts))
- **feat(parser): Page-tree manipulation API.** `mergePdfs(sources, opts?)`,
  `splitPdf(src, ranges)`, and `extractPages(src, indices)` rebuild a fresh,
  self-contained document by deep-copying each kept page and its **transitive
  object graph** (`/Contents`, `/Resources`, fonts, XObjects, ExtGState) into a
  new contiguous object-number space, then wiring a flat `/Pages` tree,
  `/Catalog`, xref, and trailer. This avoids production-unsafe in-place surgery
  (relocating `/Kids`, rewriting `/Parent` chains). **Safety:** encrypted
  sources are rejected; signatures and `/AcroForm` are always dropped (page
  edits invalidate `/ByteRange`); only self-contained URI `/Link` annotations
  are kept (or all dropped via `dropAnnotations`); inherited
  `MediaBox`/`CropBox`/`Rotate`/`Resources` are resolved and inlined; copy is
  cycle-safe and **bounded-depth** (capped recursion guards against adversarial
  nesting / ref-chains); every result carries a **deterministic content-addressed
  trailer `/ID`** (ISO 32000-1 §7.5.5) so identical inputs yield byte-identical
  output; merge is capped at 50 sources. Output is **not** claimed PDF/A.
  This **unblocks `pdfnative-mcp`'s `merge_pdfs` and `split_pdf`**, which were
  waiting on exactly this upstream API. New `src/parser/pdf-pagetree.ts`;
  `mergePdfs` / `splitPdf` / `extractPages` + `PageRange` / `MergeOptions`
  exported. ([src/parser/pdf-pagetree.ts](../src/parser/pdf-pagetree.ts))
- **feat(colr): COLRv1 advanced compositing.** The colour-emoji engine now
  resolves two more COLRv1 paints. **`PaintSweepGradient`** (conic) becomes a
  new `SweepGradientPaint` and renders as a fan of flat-colour triangular
  wedges clipped to the glyph outline — PDF has no native conic shading, so this
  stays pure path operators with no extra resource. **`PaintComposite`** maps to
  PDF `/BM` blend modes when the composite mode is expressible: `SRC_OVER` →
  Normal, plus `Multiply`, `Screen`, `Overlay`, `Darken`, `Lighten`,
  `ColorDodge`, `ColorBurn`, `HardLight`, `SoftLight`, `Difference`,
  `Exclusion`, `Hue`, `Saturation`, `Color`, `Luminosity`. Porter-Duff
  structural modes (Clear / Src / Dest / Xor / Plus / …) and `PaintMask` /
  variable paints continue to fall back to the monochrome font — output is never
  garbled. `ColorLayer` gains an optional `blendMode`; `ColorPaint` gains
  `SweepGradientPaint`. ([src/fonts/colr-parser.ts](../src/fonts/colr-parser.ts), [src/core/pdf-color-glyph.ts](../src/core/pdf-color-glyph.ts))

## API additions

| Symbol | Kind | Purpose |
|---|---|---|
| `OutlineItem` | type | Bookmark tree node (`DocumentParams.outline`) |
| `PageLabelRange`, `PageLabelStyle` | type | Page-label ranges (`DocumentParams.pageLabels`) |
| `streamToFile`, `StreamToFileResult` | fn / type | Stream a PDF straight to disk (Node) |
| `mergePdfs`, `splitPdf`, `extractPages` | fn | Page-tree manipulation |
| `PageRange`, `MergeOptions` | type | Page-tree API options |
| `SweepGradientPaint` | type | COLRv1 sweep paint; `ColorLayer.blendMode` added |

All additions are additive; no existing signature changed.

## Downstream integration notes

- **pdfnative-mcp** can now implement `merge_pdfs` and `split_pdf` on the new
  `mergePdfs` / `splitPdf` / `extractPages` API instead of unsafe raw-primitive
  page-tree surgery. `extract_pages` is also available. `redact_pdf` remains
  blocked on a separate annotation read/write API (planned for v1.5.0).
- **pdfnative-cli** and **pdfnative-react** can re-pin `pdfnative@^1.4.0`;
  bookmarks, page labels, and `streamToFile` are surfaced through the document
  builder and streaming APIs respectively.

## Compatibility

- **Zero runtime dependencies** (unchanged).
- **Backward-compatible:** every feature is additive or opt-in. Documents that
  do not set `outline` / `pageLabels` and do not register a colour-emoji font
  are byte-identical to v1.3.0.
- **Node + browser:** `streamToFile` is Node-only (throws elsewhere) via a
  dynamic import; the rest of the surface is environment-agnostic.
