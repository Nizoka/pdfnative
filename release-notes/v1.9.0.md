# pdfnative v1.9.0

<!-- GitHub Release title: v1.9.0 — conformance and fidelity: full UAX #9, 32 scripts, ToUnicode for every shaper, spot colours and the PDF/A + PDF/X dual claim, JPEG 2000, proven compatibility -->

_Released 2026-10-24_

The conformance and fidelity release. Every glyph of every shaper is extractable, bidirectional text follows the whole of UAX #9, five more Indic scripts join the engine (32 in all), the press gets spot colours and a file that is both PDF/A-2 and PDF/X-4, images gain JPEG 2000, embedded subsets shrink by up to 61 %, and thirteen issues close. Underneath, the zero-breaking-change policy is proven on every pull request: the 1.8.0 test suite and API registry run against 1.9.0, Windows and macOS are required checks, and the release pipeline attests the bytes the registry serves. 100 % backward-compatible with v1.8.0 — no export removed or renamed, two calls behave differently by design (below), and output bytes move only where the previous output was wrong, each cause in the compatibility ledger.

## Highlights

- **Full UAX #9** — embeddings, overrides and isolates, bracket pairs, the neutral rules, per-paragraph resolution; `direction: 'auto'` aligns right-to-left paragraphs to the right and justifies them in visual order; every line of the Unicode BidiCharacterTest passes ([#92]). → [Right-to-left documents](https://pdfnative.dev/guides/rtl.html)
- **32 scripts** — Gujarati, Gurmukhi, Kannada, Malayalam and Odia on the Indic engine, five bundled Noto modules (36 in all). → [All-scripts playground](https://pdfnative.dev/playgrounds/all-scripts.html)
- **ToUnicode for every shaper's glyphs** — the encoded code point wins, every shaper reports `cps`, Thai and Lao sara am carry `/ActualText` untagged, and level U is guarded by `PDFA_GLYPH_WITHOUT_UNICODE` ([#84], [#87]).
- **Logical-order extraction, tagged or not** — an untagged run whose glyphs are not in the order of its text (an Indic pre-base vowel sign or reph, a split vowel sign, a Khmer or Myanmar pre-base vowel, a Thai tone mark set before a below vowel) carries its text as `/Span /ActualText`, what Chrome and Skia write; `extractText()` and every reader return the source string; `layout.actualText: false` opts out. A character no registered font covers is now named by `TEXT_GLYPH_NOT_COVERED` instead of silently becoming a box or a `?`.
- **Spot colours and the dual claim** — `/Separation` inks and `/DeviceN` mixes with process alternates; PDF/A-2b or 2u and PDF/X-4 in one file; `validatePdfX()` reads inside XObjects. → [Print guide](https://pdfnative.dev/guides/print.html)
- **JPEG 2000** — `/JPXDecode` pass-through with the colour and opacity the codestream declares. → [Images guide](https://pdfnative.dev/guides/images.html), [Images playground](https://pdfnative.dev/playgrounds/images.html)
- **Lean embedded subsets** — a `cmap` over the kept glyphs, a format-3 `post`, no `gasp`: Noto Sans 108.9 → 42.4 KB for one paragraph.
- **Compatibility, proven** — `compat-previous` replays the 1.8.0 suite (134 files, 3114 tests) against 1.9.0 on every pull request; `api-compat` holds the 503 exports, 9 diagnostics and 23 build errors of 1.8.0; Windows and macOS required; the parser surface fuzzed; the release pipeline at SLSA Build L2. → [SECURITY.md §Compatibility promise](https://github.com/Nizoka/pdfnative/blob/main/SECURITY.md#compatibility-promise)

## Security

- **fix(crypto): `sha256()` and the SHA-512 core wrote only the low word of the FIPS 180-4 message length** (CWE-682). An input of 2^29 octets (512 MiB) or more produced a wrong digest, silently; every shorter input was unaffected. Affects every release up to 1.8.0 for inputs of that size — document hashing for signatures over files above 512 MiB, and the AES-256 key derivation's hashes are far below the bound. Fixed by `writeBitLengthBE`, shared by both cores, locked at the 2^29 boundary on the helper.
- **fix(parser): a stray `)`, `{` or `}` spun the tokenizer forever** (CWE-835). The keyword reader returned an empty token without advancing, so every token loop — the ToUnicode CMap reader among them — hung on a one-byte corruption of any PDF handed to `extractText()` or the reader. Found by the new fuzz targets; consumed as a one-byte keyword since 1.9.0.
- **fix(tools): `parseFontData()` read past the end of a malformed font** (CWE-125, a `RangeError` rather than a refusal). The reader is bounds-checked in both generators.
- **Hardening:** the release pipeline refuses anything but a `v*` tag before any approval, holds `id-token: write` only where no dev-dependency code runs, installs nothing in the publishing job, pins the npm client by the SHA-512 of its tarball, restores no dependency cache, and attests the registry's bytes; CodeQL runs `security-extended` with the `actions` language; Dependabot waits seven days; the workflows are linted on every pull request; the parser surface is fuzzed by ClusterFuzzLite. `extractText()` reports an over-cap stream instead of returning a page without its text ([#89]).

## Fixed

- **fix(crypto): SHA-256 / SHA-512 length word** — see Security.
- **fix(core): deep descenders clipped in table rows** ([#80]); **a table of contents longer than its page** overflowed the margin ([#83]); **`inspectDocumentLayout()`** agrees with the build.
- **fix(chart): a series without `label` threw a `TypeError`**; legend width measured with the context's metrics in Unicode mode ([#82]).
- **fix(parser): PDF text strings** decoded per ISO 32000-1 §7.9.2.2 in `/Info`, outlines, page labels and signature `/T`; non-Latin-1 text written to `/P`, `/T`, `/V`, `/Opt` no longer truncated ([#85]).
- **fix(core): `extraCertificates` referenced from every `/VRI`** ([#90]); **an annotation type outside the union throws** ([#91]).
- **fix(shaping): BiDi** — punctuation affinity, unpaired brackets, per-line resolution (C1–C3, [#92]); General Punctuation and whitespace classes corrected to the UCD; **Malayalam `pref`** and a ligature swallowing its base in the Indic engine.
- **fix(core): the DeviceN tint transform used `repeat`**, which is not an ISO 32000-1 Table 42 operator — Acrobat refused the page ("Invalid Function resource") of every document painting an `{ inks }` mix. The type-4 function now pops the tints one by one and leaves the clipping to `/Range` (§7.10.1); the `/DeviceN` array carries a `/Colorants` attributes dictionary (ISO 19005-2 §6.2.4.4, veraPDF PASS for a mix under PDF/A-2b); `validatePdfX()` reads every type-4 tint transform the content selects and reports an operator outside Table 42 or a procedure outside `if` / `ifelse`. `print/print-spot-colours` regenerated.
- **fix(core): Helvetica fallback runs in Unicode mode were advanced by the bucketed estimate** while the viewer drew the AFM advances — a gap or an overlap at every script boundary of a mixed line, and right-aligned lines short of the margin (visible on `bidi/bidi-uax9-conformance`). Every fallback run is measured with the AFM widths now. — **C17**
- **fix(shaping): the second part of a split vowel sign carried no code point** (Bengali ো ৌ, Tamil ொ ோ ௌ, Sinhala ේ ො ෝ ෞ, Kannada ೀ ೇ ೈ ೊ ೋ, Malayalam ൊ ോ ൌ, Odia ୈ ୋ ୌ), so one glyph id stood for several signs in `/ToUnicode` and Odia ୈ left a glyph without a Unicode value (`PDFA_GLYPH_WITHOUT_UNICODE` under level U). Each part now names its code point of the canonical decomposition (ୋ → U+0B47 U+0B3E): every glyph is mapped, and the extracted text is the NFD form, which `normalize('NFC')` turns back into the source. Folded into C4.
- **fix(parser): `PdfStreamLimitError` pointed every filter at `setMaxInflateOutputSize()`**, which only moves the FlateDecode cap; the ASCIIHex, ASCII85, LZW and RunLength decoders carry a fixed 256 MiB cap of their own, and the message now names the remedy that applies (`onStreamError: 'skip'`). Classify by `code === 'PDF_STREAM_LIMIT'`, not by the text.
- **fix(parser): the tokenizer's empty keyword**; **fix(tools): `parseFontData()` bounds** — see Security.
- **fix(core): a registered font no character reached was embedded whole** — `financial/sample-multi` carried twenty-two unused programs (12.5 MB for one page) and `tagged/tagged-pdfa2u-taitham` the 2 MB Noto Sans variable font it never drew. Both builders now embed the `.notdef`-only lean subset with `/W []`; the font object, its descriptor and ToUnicode stay (ISO 19005-2 §6.2.11.4.1 wants a program behind every referenced font), object numbering is unchanged. — **C18**
- **fix(shaping): a ZWJ after a final virama was dropped before the font saw it**, so the pre-5.1 spelling of a Malayalam chillu (consonant + virama + ZWJ) drew a consonant with a visible chandrakkala instead of ൻ ൽ ർ ൾ ൺ, and Devanagari क्‍ lost its explicit half form. The joiner stays in its syllable and requests the half form (HarfBuzz `halant_group`); the glyph names the three code points it came from. — **C19**
- **fix(samples): six generators set an arrow (U+2192) no font covers** — a `.notdef` box in `shaping/shaping-tamil` (the Tamil font), a silent `?` on the base-14 path in six others; `diverse/diverse-medical-hi` wrote a Greek mu the Devanagari font lacks for µL. Found by `TEXT_GLYPH_NOT_COVERED` on the first `test:generate` that carried it.
- **fix(shaping): Devanagari ई was drawn as इ + a hook that named nothing** (Noto Sans Devanagari splits the letter through a multiple substitution, and only the first piece carried the code point): `नई दिल्ली` raised `PDFA_GLYPH_WITHOUT_UNICODE` under level U and `इकाई` extracted as `इक ाइर्`. Every piece of a multiple substitution names the source code point now, and the run carries its text as `/ActualText` (C20).
- **fix(core): the operand-string form of a spot colour** (`'/Spot_Name 1'`) accepted any non-blank name; it is held to the name alphabet `pdfNameEncode` writes, so no delimiter can reach the content stream. `{ spot }` values were always validated against the declaration.
- **fix(parser): `extractText()` spaced the letters of wide glyphs** — the word-gap heuristic estimated the previous run's width at half an em per character while the decoder had computed the exact `/W` advance, so a Malayalam, Kannada or Khmer letter wider than 0.75 em drawn in its own text object (`അവൻ` → `അ വ ൻ`) earned a space. Each run carries its measured width now.
- **fix(ci):** the required checks no longer stay pending on a docs-only pull request; a branch `workflow_dispatch` can no longer publish; the attest job attests the registry's bytes, not a rebuild; `package-manager-cache: false` on every release setup-node; the multi-language sample had been silently skipped by a stale script-count guard and is generated again.

## Upgrade

No public API was removed or renamed; `tests/tools/api-compat.test.ts` holds every 1.8.0 export, diagnostic code and build-error message to the current registries, and the 1.8.0 test suite itself passes against 1.9.0 (`npm run compat:previous`: 134 files, 3114 tests; fourteen exclusions for the reasons listed in `tests/compat/allow-1.8.0.json`). Drop-in replacement for v1.8.0 for every program that does not rely on the two behaviours below, and output is byte-identical for existing inputs except where the previous output was wrong — each cause is a numbered ledger entry, and every moved sample is re-anchored to 1.9.0 in `tests/regression/baselines/samples.sha256.json` (166 of 292 moved, 126 carried forward, 19 added).

Two calls behave differently:

- **`extractText()` throws `PdfStreamLimitError`** (code `PDF_STREAM_LIMIT`) when a stream exceeds the inflate cap, instead of returning the page without its text. Pass `onStreamError: 'skip'` for the 1.8.0 lenience, or `'throw'` to report any undecodable stream ([#89]). — **C13**
- **`buildDocumentPDFBytes()` / `buildPDFBytes()` accept `tagged: 'pdfa2b' | 'pdfa2u'` next to `pdfx: 'pdfx4'`.** The single 1.8.0 refusal (`layout.pdfx and layout.tagged cannot be combined …`) became two level-specific messages, for PDF/A-1b and PDF/A-3b; code that matched on the old text must match the new ones (`docs/data/errors.json`). — **C14**

Compatibility ledger — deliberate output changes, each wrong before:

- **C1 — Neutral punctuation in right-to-left paragraphs** follows UAX #9 N1–N2: a full stop, comma or question mark between two Arabic or Hebrew words, or at the paragraph edge, takes the paragraph direction instead of attaching to the preceding Latin word ([#92]). Every right-to-left sample (`bidi/*`, `doc-arabic`, `doc-hebrew`, `doc-persian`, `doc-urdu`, the Arabic and Hebrew alphabet plates, `extreme/*bidi*`) is re-anchored.
- **C2 — Explicit embeddings and overrides** (`LRE`, `RLE`, `LRO`, `RLO`, `PDF`) resolve with the standard's levels and directions; the 1.3.0 "lite forcing" that stripped inner controls and kept overridden Arabic in logical order is gone. `bidi/bidi-embeddings-showcase` re-anchored.
- **C3 — Per-paragraph resolution and isolates.** Levels are resolved once over the whole paragraph (P2–I2) and only L1–L4 run per line, so wrapping no longer changes a line's neighbours; isolates are matched by BD9 and resolved inside the paragraph; brackets inside a Latin run of an Arabic paragraph are paired (N0) and mirrored (L4). Samples as C1.
- **C4 — ToUnicode for every shaper.** The code point actually encoded has priority over the inverted cmap, every shaper reports `cps`, untagged Thai and Lao sara am carry `/Span /ActualText` ([#84], [#87]). Every sample embedding a CIDFont re-anchors its `/ToUnicode` stream.
- **C5 — Table rows with deep descenders** reserve the deepest descender of their text and lift the baseline; Latin rows are byte-identical ([#80]). `tables/*`, `doc-myanmar`, `doc-khmer`, `doc-thai`, the financial and multi-font samples re-anchored where such text sits in a table.
- **C6 — Lean embedded subsets.** Every CIDFontType2 `FontFile2` carries a `cmap` over the kept glyphs, a format-3 `post` and no `gasp` (outlines, metrics, names and hinting untouched): every sample embedding a bundled font changes bytes and shrinks.
- **C7 — Mark anchors through every class.** `positionMarkOnBase` and the Khmer, Myanmar, Tibetan and USE shapers read every anchor triple, Tibetan runs on the OpenType engine, and the Tibetan, Khmer, Myanmar, Tai Tham and Cham modules carry their layout tables ([#81]). `doc-tibetan`, `doc-khmer`, `doc-myanmar`, `doc-taitham`, `doc-cham`, their alphabet plates and the shaping showcases re-anchored; the visual baselines of arabic, doc-devanagari, doc-telugu, doc-bengali, doc-lao and doc-thai regenerated.
- **C8 — Chart legend width in Unicode mode** is measured with the context's metrics ([#82]); `charts/*` with CIDFont legends shift by the difference.
- **C9 — A table of contents longer than its page** breaks at entry boundaries and continues on the following pages ([#83]); the `toc/*` sample with long contents re-anchored; a fitting TOC is byte-identical.
- **C10 — U+202F on the base-14 path** (`punctuationSpacing: 'fr'`) is a `TJ` adjustment of 167/1000 em instead of an ordinary space; the French `typography/*` samples re-anchored.
- **C11 — Page transparency group.** A page that paints with constant alpha carries `/Group << /S /Transparency /CS … /I true >>`; `watermark/*` and `emoji/*` re-anchored; never under PDF/A-1.
- **C12 — Tagged table semantics.** `/TH` carries `/A << /O /Table /Scope /Column >>` and an `/ID`, `/TD` names its headers, `/StructTreeRoot` registers an `/IDTree`; every tagged sample with a table re-anchored.
- **C13 / C14** — the two behaviour changes above.
- **C15 — Font module headers** carry the font's copyright statement; module bytes change, the glyph data does not.
- **C16 — `scanDeviceColour()` reports `named`**, the `/Separation` and `/DeviceN` names a stream selects; an added field, every 1.8.0 field unchanged.
- **C17 — Helvetica fallback runs measured with the AFM advances.** In Unicode mode a Latin word, number or bracket that no registered font covers is drawn with unembedded Helvetica; the next run of the line used to start at the bucketed estimate of its width (500 / 680 / 556 per character class) while the viewer drew the real advances — a gap after `(pdfnative library)`, an overlap after `%`, right-aligned lines short of the margin. Every such run now advances by the AFM width, whatever `typography.metrics` says (the pure base-14 path keeps its `'approximate'` default). Every document mixing a registered non-Latin font with uncovered Latin text re-anchors: `bidi/*`, `doc-arabic`, `doc-hebrew`, `doc-persian`, `doc-urdu` and the other language documents without a Latin module, `extreme/*bidi*`, the multi-font showcases; a document with a Latin module registered, or Latin-only, is byte-identical.
- **C18 — A registered font no character reaches** embeds a `.notdef`-only lean subset with `/W []` instead of the whole program; its five objects stay and the numbering does not move. `financial/sample-multi`, `tagged/tagged-pdfa2u-taitham` and `bidi/bidi-arabic-shaping` (a Hebrew module registered without Hebrew text) re-anchored; a document whose every registered font is used is byte-identical.
- **C19 — A ZWJ after a final virama stays in its syllable and requests the half form** (HarfBuzz `halant_group = z? H (ZWJ N?)?`): Malayalam ന്‍ ല്‍ ര്‍ ള്‍ ണ്‍ draw the chillu glyph of ൻ ൽ ർ ൾ ൺ through the font's `akhn` feature (Noto Sans Malayalam has no rule for ൿ, which keeps its chandrakkala), Devanagari क्‍ takes its half form (the chillu glyph names its three code points, the half form its two — the joiner leaves no glyph). Inside a syllable the same rules hold: a ZWJ after a halant stops the base search (त्‍र is half ta + ra, not ta + rakar), a pre-base sign is not placed after such a halant (ट्‍यि), and a nukta between the consonant and the halant keeps the request (क़्‍); Sinhala keeps its virama + ZWJ conjunct rule. No existing sample carried the sequences; `shaping/shaping-malayalam` is added.
- **C20 — Untagged `/Span /ActualText` on every left-to-right shaped run whose glyph order differs from its text** — an Indic pre-base vowel sign or reph, a split vowel sign reported as its NFD parts, a Khmer or Myanmar pre-base vowel, a Thai or Lao cluster whose tone mark is set before a below vowel; what Chrome and Skia write, and what makes `extractText()` and every reader return the source string in logical order. Right-to-left runs are left alone (readers reverse them through the bidi algorithm; an Arabic run's text is already visual). The tagged emitters pass their structure span's text and never nest a second span, so a tagged sara am document loses one redundant span. `layout.actualText: false` opts out. Re-anchored: every untagged sample with Indic, Sinhala, Khmer, Myanmar, Tai Tham, Cham, Thai or Lao text — `alphabet/*` and `document/doc-*` of those scripts, `shaping/*`, `extreme/*`, `financial/sample-hi`, `financial/sample-th`, `compression/compressed-thai`, `diverse/diverse-medical-hi`, `diverse/diverse-recipe-th`, `currency/currency-multi`, `font/font-subsetting-multiscript`, `document/doc-multi-language`.
- **C21 — Subset font names carry the six-letter tag** of ISO 32000-1 §9.6.4: `/BaseFont` and `/FontName` of every embedded subset read `ABCDEF+NotoSans-Regular`, the tag derived from the face name and the kept glyph set (deterministic — the same text gives the same tag). Preflight tools and font-merging RIPs read it to tell two subsets of one face apart. Under PDF/A-1 the name stays bare: ISO 19005-1 §6.3.5 asks a tagged CIDFont subset for a `/CIDSet` stream the builders do not write yet (roadmap), and veraPDF 6.3.5-3 fails without it. Every sample embedding a font outside PDF/A-1 re-anchors; glyphs, widths and programs are unchanged.
- **C22 — Kannada and Telugu vowel signs sit before the subjoined consonants** (HarfBuzz `POS_BEFORE_SUB`): every above and below sign and the short right signs (Kannada ಾ ು ೂ, Telugu up to ూ) follow the base directly, so the font's consonant + sign ligature forms when the consonant carries a subscript — ಕ್ಕಿ, ಸ್ತ್ರೀ, ಪ್ರೀತಿ, క్కి. Before, the sign followed the subscript: a spacing ಿ in Kannada, a Telugu ి drawn 483 units to the right of its consonant. ೃ ೄ ృ ౄ and the length marks keep their place after the subjoined consonants. `alphabet/alphabet-kannada`, `alphabet/alphabet-telugu`, `document/doc-kannada`, `document/doc-telugu`, `shaping/shaping-telugu`, the multi-script showcases and the Kannada and Telugu visual fixtures re-anchored.
- **C23 — Myanmar e-vowel before the medial ra**, and one cluster for a medial ra followed by medial wa or ha (HarfBuzz `VPre` before `PRE_C`): ကြေ, မြေ draw `ေ ြ က`; ကြွေ, မြွေ keep the wa on the base instead of a cluster of its own. `document/doc-myanmar`, `alphabet/alphabet-myanmar`, `shaping/shaping-myanmar` and `shaping/use-lite-clusters` re-anchored where such words occur.
- **C24 — Khmer two-part vowels draw their own right piece.** ើ ឿ ៀ ោ ៅ decompose as HarfBuzz's `decompose_khmer` does — the pre-base េ, then the sign itself — and the sign's presentation glyph goes through the font's `abvf` / `psts` single substitution: ើ ends in the anchored above mark ី, ៅ ឿ ៀ in their hooks, ោ in ា as before. Until now ើ ៅ ឿ ៀ were drawn with the right part of ោ, ី, ឹ, so ទៅ read ទោ and ដើម្បី read ដោម្បី. `document/doc-khmer`, `shaping/shaping-khmer`, `font/font-subsetting-multiscript`, `document/doc-multi-language` and the Khmer visual fixture re-anchored (the alphabet plate lists the signs alone and does not move).
- Sample changes, all content: `document/doc-showcase-all-blocks` says 32 scripts; `document/doc-multi-language` is generated again (it had been skipped by a stale guard since the five Indic scripts joined) and carries them; `financial/sample-multi` registers the ten fonts its rows use and is tagged (PDF/A-2b, `/Table` `/TR` `/TH` `/TD` with `/Scope`, every cell's text as `/ActualText`), so its Arabic, Hebrew and Hindi cells extract column by column in logical order — 25 PDF/A-claiming samples now; `tagged/tagged-pdfa2u-taitham` registers the Latin face first so its English prose is set in Noto Sans; `print/print-spot-colours` paints each plate of its ink-coverage chart in that plate's ink (`ChartSeries.colors`); six samples replace an arrow no font covers with words or `=` (`shaping/shaping-tamil`, `compression/compressed-encrypted-aes128`, `crypto/crypto-showcase`, `parser/parser-xref-chain`, `signature/digital-signature-info`, `font/font-subsetting-overview`) and `diverse/diverse-medical-hi` writes µL with the micro sign; `shaping/shaping-malayalam` is new (311 samples).

Known limits, documented in the guides: the Indic engine's five new scripts are held by golden tests against the bundled fonts, the regenerated visual fixtures and a HarfBuzz-referenced review of every sample word, not yet by a native reader — reports welcome; neither the catalog nor the structure tree carries `/Lang`, and rules and table borders are not marked `/Artifact`, so a tagged file passes PDF/A-2 but not yet PDF/UA-1 (1.9.1); a Thai above vowel + tone mark pair may extract in geometric order (`ตั้ง` → `ตัง้`; the ToUnicode is right and the C20 span covers reordered clusters); right-to-left runs carry no untagged `/ActualText` (C20 leaves them to the reader's bidi reversal), so a mixed line extracts in geometric order unless the document is tagged; the Thai and Lao shapers set a tone mark before a below vowel in the content stream (canonically equivalent, covered by the span, unchanged in rendering); colour bars paint process inks only; PDF/A-1 and PDF/A-3 do not combine with PDF/X-4; JPEG 2000 is passed through, never decoded (the `images/*` fixtures are flat mid-grey codestreams by design).

## Downstream integration notes

For pdfnative-cli, pdfnative-mcp and pdfnative-react, which pin `^1.8.0` and therefore resolve to 1.9.0:

- **Type widening.** `PdfColor` gains `PdfSpotColor` (`{ spot, tint? }`) and `PdfInkMix` (`{ inks }`); `PdfColorSpace` gains `'separation' | 'devicen'`; `detectImageFormat()` may return `'jpx'`; `ParsedImage.filter` may be `'/JPXDecode'` and `ParsedImage.jpx` is set for a JPEG 2000 image; `ChartSeries.label` is optional and `ChartSeries.colors` (one colour per value, bar charts) is new; `MarkupAnnotation` gains the `link` member; `PdfDiagnosticCode` gains `PDFA_GLYPH_WITHOUT_UNICODE`, `PDFA1_JPX_IMAGE`, `PDFA_JPX_IMAGE`, `TEXT_GLYPH_NOT_COVERED` (a character no registered font covers — a wrapper that surfaces diagnostics now reports boxes and `?` substitutions it used to pass silently); `toWinAnsi()` and `pdfString()` take an optional second argument; `EncodingContext` gains `getUncoveredCodepoints()` and `actualText`, and `createEncodingContext()` takes `actualText` as a sixth optional argument; a subset font's `/BaseFont` and `/FontName` carry the six-letter tag (`ABCDEF+NotoSans-Regular`, C21) — a wrapper that lists or matches font names should strip `^[A-Z]{6}\+`.
- **Sample corpus:** 311 samples, 25 of them PDF/A-claiming (`financial/sample-multi` is tagged now) — a downstream canary that counts them moves from 310 / 24.
- **New layout options to expose:** `direction` (`'auto' | 'ltr' | 'rtl'`, also per paragraph), `print.spotColours`, `actualText` (opt-out), the `pdfx` + `tagged: 'pdfa2b' | 'pdfa2u'` combination; `extractText({ onStreamError })`.
- **New error class and code to classify:** `PdfStreamLimitError` / `PDF_STREAM_LIMIT` from `extractText()` and the decode filters — a wrapper that mapped an empty page to "no text" now receives an error for an over-cap stream. **Replaced message:** the single PDF/A + PDF/X refusal is now one message per excluded level (`docs/data/errors.json`).
- **New exports:** `decodePdfTextString`, `composeLtvData` (+ `LtvMaterial`, `ComposeLtvOptions`), `ocspResponseMatchesCertificate`, `ecdsaVerifyHash`, `ecdsaSignHash`, `encodeDerSignature`, `decodeDerSignature`, `resolveBidiLevels`, `bidiLineLevels`, `bidiRunsForLine`, `parseJPX`, `JpxInfo`, `TextDirection`, `PdfSpotColor`, `PdfInkMix`, `SpotColourDef`, `PdfStreamLimitError`; on `pdfnative/tools`: `buildSyntheticGrayProfile`, `buildSyntheticCmykProfile` (pdfnative-cli can drop its vendored copy). 39 exports added, none removed (542 in `docs/assets/api.json`).
- **Five language keys and font modules:** `gu`, `pa`, `kn`, `ml`, `or` → `noto-gujarati`, `noto-gurmukhi`, `noto-kannada`, `noto-malayalam`, `noto-oriya`; hand-enumerated surfaces (pdfnative-cli `--font` allow-list and `--strict` help, pdfnative-mcp `lang` enum, pdfnative-react font map) should add them. Script count 32, module count 36.
- **Images:** wrappers that validate extensions should accept `.jp2`, `.j2k`, `.jpx`; PDF/A-1 flags them with `PDFA1_JPX_IMAGE` (a warning; an error under `strict`).
- **Spot colours** need a declaration in `print.spotColours`; a JSON DocSpec carrying `{ spot }` colours without it is refused with a named error. A `/DeviceN` array has five elements (the attributes dictionary with `/Colorants` is the fifth); a tool that reads the array shape should not assume four.
- **`PdfStreamLimitError.message`** differs between FlateDecode (`setMaxInflateOutputSize()`) and the fixed-cap filters (`onStreamError: 'skip'`); classify by `code`, never by the text.
- **Annotations:** `annotate_pdf` / `annotate` can offer `link` with `url`. **LTV:** `add_ltv` can take offline material through `composeLtvData` (`match: 'chain' | 'all'`).
- **Font modules** are rebuilt (a `Copyright:` header line; the Tibetan, Khmer, Myanmar, Tai Tham and Cham modules carry `otl` for their scripts); consumers that vendor module files should refresh them.
- **Bytes move** for every document embedding a font (C6), every right-to-left document (C1–C3), every untagged document with Indic, Sinhala, Khmer, Myanmar, Tai Tham, Cham, Thai or Lao text (C20, an `/ActualText` span per reordered run) and every document registering a font it never draws (C18, far smaller); a downstream byte manifest is rebaselined once against 1.9.0. A wrapper that exposes `extractText()` returns logical-order text for those scripts now, tagged or not.
- **CI:** downstream repositories that copied `publish.yml`, `ci.yml` or `setup-verapdf` can take the guard → build → publish → attest pipeline, the Windows/macOS matrix and the `home` output of the action from this release.
