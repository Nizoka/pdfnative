# pdfnative v1.9.0

<!-- GitHub Release title: v1.9.0 — conformance and fidelity: full UAX #9, 32 scripts, ToUnicode for every shaper, spot colours and the PDF/A + PDF/X dual claim, JPEG 2000, proven compatibility -->

_Released 2026-10-29_

The conformance and fidelity release. Every glyph of every shaper is extractable, bidirectional text follows the whole of UAX #9, five more Indic scripts join the engine (32 in all), the press gets spot colours and a file that is both PDF/A-2 and PDF/X-4, images gain JPEG 2000, embedded subsets shrink by an order of magnitude, and thirteen issues close. Underneath, the zero-breaking-change policy is proven on every pull request: the 1.8.0 test suite and API registry run against 1.9.0, Windows and macOS are required checks, and the release pipeline attests the bytes the registry serves. 100 % backward-compatible with v1.8.0 — no export removed or renamed, two calls behave differently by design (below), and output bytes move only where the previous output was wrong, each cause in the compatibility ledger.

## Highlights

- **Full UAX #9** — embeddings, overrides and isolates, bracket pairs, the neutral rules, per-paragraph resolution; `direction: 'auto'` aligns right-to-left paragraphs to the right and justifies them in visual order; every line of the Unicode BidiCharacterTest passes ([#92]). → [Right-to-left documents](https://pdfnative.dev/guides/rtl.html)
- **32 scripts** — Gujarati, Gurmukhi, Kannada, Malayalam and Odia on the Indic engine, five bundled Noto modules (36 in all). → [All-scripts playground](https://pdfnative.dev/playgrounds/all-scripts.html)
- **ToUnicode for every shaper's glyphs** — the encoded code point wins, every shaper reports `cps`, Thai and Lao sara am carry `/ActualText` untagged, and level U is guarded by `PDFA_GLYPH_WITHOUT_UNICODE` ([#84], [#87]).
- **Logical-order extraction, tagged or not** — an untagged run whose glyphs are not in the order of its text (an Indic pre-base vowel sign or reph, a split vowel sign, a Khmer or Myanmar pre-base vowel, a Thai tone mark set before a below vowel) carries its text as `/Span /ActualText`, what Chrome and Skia write, and so does every right-to-left run (its logical text, as Skia writes for reversed clusters); `extractText()` and every reader return the source string, an untagged Arabic or Hebrew line as typed; `layout.actualText: false` opts out. A character no registered font covers is now named by `TEXT_GLYPH_NOT_COVERED` instead of silently becoming a box or a `?`.
- **Spot colours and the dual claim** — `/Separation` inks and `/DeviceN` mixes with process alternates; PDF/A-2b or 2u and PDF/X-4 in one file; `validatePdfX()` reads inside XObjects. → [Print guide](https://pdfnative.dev/guides/print.html)
- **JPEG 2000** — `/JPXDecode` pass-through with the colour and opacity the codestream declares. → [Images guide](https://pdfnative.dev/guides/images.html), [Images playground](https://pdfnative.dev/playgrounds/images.html)
- **Compact embedded subsets** — the glyphs a document uses are renumbered into its CID space (glyph i of the embed is CID i), so a subset costs its outlines and nothing of the source font's glyph count; a `cmap` over the kept glyphs, a format-3 `post`, no `gasp`. Noto Sans 108.9 → 6.3 KB and Noto Sans JP 275.0 → 9.6 KB for one paragraph; `financial/sample-multi` 824.6 → 100.7 KB.
- **Compatibility, proven** — `compat-previous` replays the 1.8.0 suite (128 files, 2901 tests) against 1.9.0 on every pull request; `api-compat` holds the 503 exports, 9 diagnostics and 23 build errors of 1.8.0; Windows and macOS required; the parser surface fuzzed; the release pipeline at SLSA Build L2. → [SECURITY.md §Compatibility promise](https://github.com/Nizoka/pdfnative/blob/main/SECURITY.md#compatibility-promise)

## Security

- **fix(crypto): `sha256()` and the SHA-512 core wrote only the low word of the FIPS 180-4 message length** (CWE-682). An input of 2^29 octets (512 MiB) or more produced a wrong digest, silently; every shorter input was unaffected. Affects every release up to 1.8.0 for inputs of that size — document hashing for signatures over files above 512 MiB, and the AES-256 key derivation's hashes are far below the bound. Fixed by `writeBitLengthBE`, shared by both cores, locked at the 2^29 boundary on the helper.
- **fix(parser): a stray `)`, `{` or `}` spun the tokenizer forever** (CWE-835). The keyword reader returned an empty token without advancing, so every token loop — the ToUnicode CMap reader among them — hung on a one-byte corruption of any PDF handed to `extractText()` or the reader. Found by the new fuzz targets; consumed as a one-byte keyword since 1.9.0.
- **fix(tools): `parseFontData()` read past the end of a malformed font** (CWE-125, a `RangeError` rather than a refusal). The reader is bounds-checked in both generators.
- **Hardening:** the release pipeline refuses anything but a `v*` tag before any approval, holds `id-token: write` only where no dev-dependency code runs, installs nothing in the publishing job, pins the npm client by the SHA-512 of its tarball, restores no dependency cache, and attests the registry's bytes; CodeQL runs `security-extended` with the `actions` language; Dependabot waits seven days; the workflows are linted on every pull request; the parser surface is fuzzed by ClusterFuzzLite. `extractText()` reports an over-cap stream instead of returning a page without its text ([#89]).
- **Dev toolchain:** vitest 4.1.12 (GHSA-qxg6-89mg-rqv8, GHSA-xp26-3454-mjgp), vite 8.3.5 (GHSA-587h-7wmj-h5pm, GHSA-r825-w8mm-5pxw, GHSA-698v-4r3x-3vcv, GHSA-9jrq-w75r-8gcw, GHSA-rq7h-c2jc-7f22, GHSA-vfpm-58rq-9qcg), brace-expansion 1.1.21 and 5.0.12 (GHSA-q2hr-2g5m-vwhr, GHSA-qhr7-859c-m2p7, GHSA-6j4f-fj2g-mc7p), source-map-js 1.2.2 (GHSA-68fv-2mgg-jv7q) — Dependabot alerts 21–29, all development scope, none shipped; `npm audit --audit-level=high` reports none. Nothing in the package changed: the samples are byte-identical. The lockfile was regenerated with npm 11.19.1 because npm 10.9 cannot rebuild the ideal tree of a project whose devDependency pdfnative-react declares a peer dependency on the project itself; `npm ci` under npm 10.9 installs it cleanly.
- **`scripts/build-guides.ts`** (the guide pre-renderer, an authoring tool outside the package) decodes `&amp;` last and strips tags to a fixed point — CodeQL js/double-escaping and js/incomplete-multi-character-sanitization, alerts 15 and 16; the 38 committed guide shells are byte-identical, and the helpers are held by a test.
- **OpenSSF Scorecard:** the `attest` job's `contents: write` (attaching the files to the release) and its `npm install pdfnative@<exact>` (what `npm audit signatures` verifies) are deliberate and documented in SECURITY.md §Code Safety; the code-review and best-practices-badge findings are acknowledged there too.

## Changed

- **Shaping fidelity** ([#81]) — mark anchors read through every class in every shaper, Tibetan on the OpenType engine, `tibt`/`khmr`/`mymr`+`mym2`/`lana`/`cham` layout tables kept by both generators; the Tibetan, Khmer, Myanmar, Tai Tham and Cham modules rebuilt.
- **`extractText()` throws `PdfStreamLimitError`** on an over-cap stream by default ([#89]).
- **The joint PDF/A + PDF/X refusal** became two level-specific messages (C14).
- **`scanDeviceColour()`** gains `named` (C16); **`buildPDF`** honours `ColumnDef.kind: 'amount'` once any column declares a kind.
- **`validatePdfX()`** also reads the type-4 tint transforms of the Separation and DeviceN spaces the content selects (ISO 32000-1 Table 42 operators, procedures only under `if` / `ifelse`).
- **Every embedded subset is lean** (C6) **and compact** (C28): a font's glyphs take CIDs in order of first use, the content streams show them by those codes and the embedded program is renumbered to match (GID i = CID i, `/CIDToGIDMap /Identity` as before), so `hmtx`, `loca` and `maxp` cover the kept glyphs only; every font module header carries `Copyright:` (C15); an unused registered font is a `.notdef`-only stub (C18).
- **Untagged shaped runs out of text order carry `/Span /ActualText`** (C20): Indic, Sinhala, Khmer, Myanmar, Tai Tham, Cham and the Thai and Lao clusters whose tone mark precedes a below vowel; `extractText()` returns the logical string from an untagged document; `layout.actualText: false` restores the 1.8.0 runs. Tagged output is unchanged — its structure spans already carried the text, and the tagged emitters no longer nest a second span for sara am. **Every untagged right-to-left run carries its logical text the same way** (C27), so an Arabic or Hebrew line extracts as typed from an untagged document too.
- **Subset font names carry the ISO 32000-1 §9.6.4 tag** (C21); **Kannada and Telugu vowel signs precede the subjoined consonants** (C22); **Myanmar e-vowel before the medial ra** (C23); **Khmer two-part vowels draw their own right piece** (C24).
- **`verify:bundle`** budgets re-measured: the `parseColor` probe moved from 4 to 6 KB because the `PdfColor` union gained spot colours and ink mixes the parser must read (4.2 KB at 1.9.0, 2.6 KB at 1.8.0); the other two probes are unchanged.
- **CI:** `ci.yml`, `codeql.yml` and the publish workflow lost their path filters; `setup-verapdf` returns its directory as an output; every audit-mode `harden-runner` carries a dated reason; the FAQ and the pipeline say SLSA Build L2.
- **`pdfnative-build-emoji-font --download`** refuses a font whose SHA-256 differs from the tested build (it used to warn and proceed); `--allow-unverified` keeps the old behaviour, `--ttf` takes a file you verified yourself. The fuzz engine's lockfile licences (BlueOak-1.0.0, CC-BY-4.0, dev-only) are allow-listed for the dependency review; the runtime-smoke server resolves every served path under the repository root; font table maps use a null prototype.
- **Repository:** line endings normalised to LF — the 276 CRLF blobs `.gitattributes` had declared `eol=lf` over since 1.8.0 are rewritten in one dedicated commit (listed in `.git-blame-ignore-revs`; nothing but carriage returns changed), and the `verify:docs` rule `eol-lf` now fails on a CRLF blob instead of warning. The generated Unicode data modules and `use-engine.ts` carry a `/*! @license */` block so the Unicode, Microsoft and HarfBuzz notices reach `dist/` (a plain comment never did); `verify:bundle` probes measure code without legal comments.

## Fixed

- **fix(crypto): SHA-256 / SHA-512 length word** — see Security.
- **fix(core): deep descenders clipped in table rows** ([#80]); **a table of contents longer than its page** overflowed the margin ([#83]); **`inspectDocumentLayout()`** agrees with the build.
- **fix(chart): a series without `label` threw a `TypeError`**; legend width measured with the context's metrics in Unicode mode ([#82]).
- **fix(parser): PDF text strings** decoded per ISO 32000-1 §7.9.2.2 in `/Info`, outlines, page labels and signature `/T`; non-Latin-1 text written to `/P`, `/T`, `/V`, `/Opt` no longer truncated ([#85]).
- **fix(core): `extraCertificates` referenced from every `/VRI`** ([#90]); **an annotation type outside the union throws** ([#91]).
- **fix(shaping): BiDi** — punctuation affinity, unpaired brackets, per-line resolution (C1–C3, [#92]); General Punctuation and whitespace classes corrected to the UCD; **Malayalam `pref`** and a ligature swallowing its base in the Indic engine.
- **fix(core): the DeviceN tint transform used `repeat`**, which is not an ISO 32000-1 Table 42 operator — Acrobat refused the page ("Invalid Function resource") of every document painting an `{ inks }` mix. The type-4 function now pops the tints one by one and leaves the clipping to `/Range` (§7.10.1); the `/DeviceN` array carries a `/Colorants` attributes dictionary (ISO 19005-2 §6.2.4.4, veraPDF PASS for a mix under PDF/A-2b); `validatePdfX()` reads every type-4 tint transform the content selects and reports an operator outside Table 42 or a procedure outside `if` / `ifelse`. `print/print-spot-colours` regenerated.
- **fix(core): Helvetica fallback runs in Unicode mode were advanced by the bucketed estimate** while the viewer drew the AFM advances — a gap or an overlap at every script boundary of a mixed line, and right-aligned lines short of the margin (visible on `bidi/bidi-uax9-conformance`). Every fallback run is measured with the AFM widths now. — **C17**
- **fix(shaping): the second part of a split vowel sign carried no code point** (Bengali ো ৌ, Tamil ொ ோ ௌ, Sinhala ේ ො ෝ ෞ, Kannada ೀ ೇ ೈ ೊ ೋ, Malayalam ൊ ോ ൌ, Odia ୈ ୋ ୌ), so one glyph id stood for several signs in `/ToUnicode` and Odia ୈ left a glyph without a Unicode value (`PDFA_GLYPH_WITHOUT_UNICODE` under level U). Each part now names its code point of the canonical decomposition (ୋ → U+0B47 U+0B3E): every glyph is mapped, and the extracted text is the NFD form, which `normalize('NFC')` turns back into the source. Folded into C4.
- **fix(parser): `PdfStreamLimitError` pointed every filter at `setMaxInflateOutputSize()`**, which only moves the FlateDecode cap; the ASCIIHex, ASCII85, LZW and RunLength decoders carry a fixed 256 MiB cap of their own, and the message now names the remedy that applies (`onStreamError: 'skip'`). Classify by `code === 'PDF_STREAM_LIMIT'`, not by the text.
- **fix(parser): the tokenizer's empty keyword**; **fix(tools): `parseFontData()` bounds** — see Security.
- **fix(core): a registered font no character reached was embedded whole** — `financial/sample-multi` carried twenty-two unused programs (12.5 MB for one page) and `tagged/tagged-pdfa2u-taitham` the 2 MB Noto Sans variable font it never drew. Both builders now embed the `.notdef`-only lean subset with `/W []`; the font object, its descriptor and ToUnicode stay (ISO 19005-2 §6.2.11.4.1 wants a program behind every referenced font), object numbering is unchanged. — **C18**
- **fix(shaping): a ZWJ after a final virama was dropped before the font saw it**, so the pre-5.1 spelling of a Malayalam chillu (consonant + virama + ZWJ) drew a consonant with a visible chandrakkala instead of ൻ ൽ ർ ൾ ൺ, and Devanagari क्‍ lost its explicit half form. The joiner stays in its syllable and requests the half form (HarfBuzz `halant_group`); the glyph names the three code points it came from. — **C19**
- **fix(samples): six generators set an arrow (U+2192) no font covers** — a `.notdef` box in `shaping/shaping-tamil` (the Tamil font), a silent `?` on the base-14 path in six others; `diverse/diverse-medical-hi` wrote a Greek mu the Devanagari font lacks for µL. Found by `TEXT_GLYPH_NOT_COVERED` on the first `test:generate` that carried it.
- **fix(shaping): Devanagari ई was drawn as इ + a hook that named nothing** (Noto Sans Devanagari splits the letter through a multiple substitution, and only the first piece carried the code point): `नई दिल्ली` raised `PDFA_GLYPH_WITHOUT_UNICODE` under level U and `इकाई` extracted as `इक ाइर्`. Every piece of a multiple substitution names the source code point now, and the run carries its text as `/ActualText` (C20).
- **fix(core): the operand-string form of a spot colour** (`'/Spot_Name 1'`) accepted any non-blank name; it is held to the name alphabet `pdfNameEncode` writes, so no delimiter can reach the content stream. `{ spot }` values were always validated against the declaration.
- **fix(parser): `extractText()` spaced the letters of wide glyphs** — the word-gap heuristic estimated the previous run's width at half an em per character while the decoder had computed the exact `/W` advance, so a Malayalam, Kannada or Khmer letter wider than 0.75 em drawn in its own text object (`അവൻ` → `അ വ ൻ`) earned a space. Each run carries its measured width now.
- **fix(core): a shaped run was one text object per glyph, and Acrobat pasted its `/ActualText` once per glyph** — Ctrl+A / Ctrl+C in Acrobat Reader on `financial/sample-multi` returned รายการไทย nine times and हिन्दी लेनदेन twelve times (one copy per `BT … ET` under the cell's span), the Arabic cells as twelve interleaved fragments, and a Tai Tham paragraph line of `tagged/tagged-pdfa2u-taitham` eighty-one times; `extractText()` and Chrome, which apply the span once, never showed it. A line or cell is now one text object: `Tf` switches the fonts inside it, every shaped run is one `TJ` array whose numbers place the glyphs (the `/W` advance against the layout's pen — GPOS offsets, zero-advance marks, the justification gap after a space), and only a mark with a vertical offset keeps a `Td` + `Tj` of its own inside the same object — the structure Skia and Chrome write. — **C25**
- **fix(shaping): a sentence-final danda sent an Odia or Gurmukhi line to the Devanagari shaper** — U+0964 sits in the Devanagari block, Devanagari is registered before the five 1.9.0 scripts, and the registry's first match took the whole line: `document/doc-odia` drew ଶିରୋନାମା with the composed ୋ glyph (Noto's dotted-circle form) in front of ର and ଗୋଟିଏ with a gap, `document/doc-gurmukhi` drew ਲਾਇਬ੍ਰੇਰੀ with an explicit virama — while every table row, danda-free, was right. The Devanagari entry now detects the Script property (the danda and double danda are Common, the Vedic tone marks U+0951–U+0954 Inherited, as HarfBuzz itemises); `containsDevanagari()` keeps its block-wide meaning. — **C26**
- **fix(ci):** the required checks no longer stay pending on a docs-only pull request; a branch `workflow_dispatch` can no longer publish; the attest job attests the registry's bytes, not a rebuild; `package-manager-cache: false` on every release setup-node; the multi-language sample had been silently skipped by a stale script-count guard and is generated again.

## Performance

- **perf(fonts): lean, compact subsets** — Noto Sans 108.9 → 6.3 KB, Arabic 44.2 → 13.5 KB, Devanagari 34.2 → 5.8 KB, JP 275.0 → 9.6 KB, SC → 7.9 KB, KR → 7.2 KB, Thai 13.8 → 5.9 KB for one paragraph each (raw bytes before Flate; measured on the bundled modules, 2026-10-27). The lean embed alone (C6) had left the retained glyph ids' `loca` and `hmtx` entries in place — 147.6 KB for three Japanese characters of a 17 936-glyph face; the compact order (C28) removes them: `financial/sample-multi` carries 57.9 KB of fonts instead of 781.1 KB.
- **perf(shaping): the UAX #9 resolver** keeps the 1.8.0 cost for text without directional controls (a fast path skips the explicit-level machinery); the full algorithm runs only when a control is present.

## Upgrade

Two calls behave differently:

A wrapper that exposes `extractText()` returns logical-order text for those scripts now, tagged or not; Acrobat Reader pastes a tagged cell once.
- **CI:** downstream repositories that copied `publish.yml`, `ci.yml` or `setup-verapdf` can take the guard → build → publish → attest pipeline, the Windows/macOS matrix and the `home` output of the action from this release.
- **`validatePdfX()` reads inside XObjects:** pdfnative-mcp's `PDF_X_CAVEATS` ("Not checked: colour inside Form XObjects and images") is stale against 1.9.0 and should drop that clause; the MCP playground quotes the server's text verbatim until the server changes it.
- **Sibling engines:** the documentation now names [zipnative](https://zipnative.dev) and [pkinative](https://pkinative.dev) beside the three satellites; a downstream README that lists the ecosystem may add the two links and [the native family guide](https://pdfnative.dev/guides/native-family.html).
- **`pdfnative-build-emoji-font`:** a wrapper that runs `--download` in a pipeline must add `--allow-unverified` to keep running past an upstream font revision, or pin the font with `--ttf`.
- **Repository line endings:** every tracked text file is LF since one dedicated commit listed in `.git-blame-ignore-revs`; a fork or a long-lived branch sees a whole-tree carriage-return diff once (`git merge -X ignore-space-at-eol` resolves it) and should run `git config blame.ignoreRevsFile .git-blame-ignore-revs`; the npm package is unaffected.
