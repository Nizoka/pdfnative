# pdfnative v1.8.0

<!-- GitHub Release title: v1.8.0 — typography, 27 scripts, CMYK & PDF/X-4 -->

_Released 2026-09-15_

The typography and print release. Long reports now typeset like documents rather than generated pages: paragraphs break across pages under widow and orphan rules, headings stay with what they introduce, body text justifies with hanging punctuation, and a registered font's pair kerning and OpenType figures apply on request. Five scripts of mainland South-East Asia join (27 in all), two of them shaped by a Universal Shaping Engine generated from the Unicode Character Database. Colour emoji gain every COLRv1 transform, variable paints and structural masks, so flags keep their shaded wave, and the bundled module carries skin tones. For print, colours can be CMYK, OutputIntents can be CMYK or Gray without breaking a PDF/A claim, printer's marks use the registration colour, and a document can claim PDF/X-4 and check itself with `validatePdfX()`. Devanagari, Bengali, Tamil, Telugu and Sinhala are shaped by one OpenType engine that applies the font's own features in the order the Indic specification prescribes — reph, half forms, subjoined consonants and pre-base vowel signs now land where the font designed them — and every font module keeps one mark-anchor class per subtable, so vowel signs, harakat, niqqud and tone marks sit at their designed height in all 27 scripts. Hausa, Yoruba, Igbo and Swahili render on the bundled Noto Sans with their combining tone marks attached. Underneath, every sample is deterministic and held byte for byte to the release that last changed it, and twenty-nine one-page language documents put every construction of a script in front of a reader who can judge it. **Backward-compatible with v1.7.0** — 58 exports added and none removed; every new capability is a new API or an opt-in option; existing inputs render byte-identically except where the previous output was wrong, and every such case, plus the four calls whose behaviour changed, is listed under Upgrade. Zero runtime dependencies, 3748+ tests across 159 files, and a consumer importing one helper now bundles that helper alone (2.6 KB for `parseColor`, down from 29.8 KB, with the bundle gate now set at 4 KB).

## Highlights

- **Typography** — `layout.typography` adds paragraph splitting with `widows` / `orphans`, `keepHeadingsWithNext`, `align: 'justify'` and `opticalMargins`, soft hyphens and a `setHyphenationProvider()` seam with `hyphenationLanguage`, ISO 80000-1 unit binding, punctuation-spacing presets and rules, exact base-14 metrics, pair `kerning`, and `fontFeatures` such as `onum` and `smcp` (with a diagnostic when a tag changes nothing). New [typography guide](../docs/guides/typography.md).
- **27 scripts and a Universal Shaping Engine** — Lao, Tai Tham, New Tai Lue, Tai Le and Cham, with the engine's categories derived from UCD 17.0.0 and one shaper registry in place of three dispatch ladders. Khmer subscripts, Myanmar kinzi and stacked marks render correctly.
- **Indic OpenType engine** — Devanagari, Bengali, Tamil, Telugu and Sinhala share one engine that reads the font's per-script GSUB features (`rphf`, `blwf`, `half`, `pstf`, `vatu`, `cjct`, `pres`, `abvs`, `blws`, `psts`, `haln`, contextual lookups included) and applies them per syllable in specification order; the reph sits over the consonant that follows the base, the Tamil i-matra stays to the right of its consonant, Telugu subjoined consonants appear, and every vowel sign takes the anchor its font declares. A rendering report on the Hindi, Tamil and Telugu samples started this work; the [text-shaping rules](../.github/instructions/text-shaping.instructions.md) describe the pipeline.
- **Latin combining marks and four African languages** — a `latin-marks` shaper attaches free-standing combining marks through the font's `ccmp` and GPOS anchors, so Yoruba ẹ́ ọ̀, Igbo ị́ and NFD text set in Noto Sans render composed; Hausa (ɓ ɗ ƙ ƴ), Yoruba, Igbo and Swahili sample plates and documents ship, all on the bundled `latin` module — no new font, no new key.
- **Language conformance documents** — twenty-nine one-page samples (`doc-thai` … `doc-polish`), one for every bundled script (the Japanese and Chinese documents already existed) and one for each of the four African languages, each with an edge-case table (what it exercises, the sample, what a correct rendering shows) held to one page by a test and to pixels by a visual baseline.
- **Colour emoji** — COLRv1 transforms (formats 12–31), variable paints at the default instance, `SRC_IN` / `DEST_IN` masks as clipping paths; 150 bundled skin-tone forms.
- **CMYK and PDF/X-4** — `[c, m, y, k]` colours, CMYK and Gray OutputIntents with RGB content kept conforming through a calibrated `/DefaultRGB` (veraPDF-validated under PDF/A-1b and 2b), registration-colour marks, `pdfx: 'pdfx4'`, and `validatePdfX()`. See the [print guide](../docs/guides/print.md).
- **Regression harness** — `npm run verify:samples` holds all 292 samples to the bytes of the release that last changed them and refuses two samples of a pair that come out identical, blocking in CI; `npm run verify:bundle` proves the published bundle tree-shakes; `npm run gate` runs every check with a twenty-line summary.

## Fixed

- **fix(core):** AcroForm `/DR` font embedded under a PDF/A claim, so interactive forms can be archival ([#74]).
- **fix(core):** `inspectDocumentLayout()` reported fewer pages than the build for documents with a table of contents ([#75]).
- **fix(core):** `setDeflateImpl()` documentation recommended implementations that produce unreadable streams; injected compressors are now validated ([#78]).
- **fix(core):** soft hyphens rendered as visible hyphens; no-break spaces measured about twice their width.
- **fix(fonts):** GSUB single substitutions read from the wrong offset, missed extension lookups and merged discretionary features; font modules advertised glyphs a subsetted face could not draw.
- **fix(shaping):** Khmer subscripts, Myanmar kinzi and stacked marks; U+061C ARABIC LETTER MARK stripped before measuring.
- **fix(fonts):** the font-module generators collapsed every GPOS mark class to class 0 and kept only the last MarkToBase subtable's bases, so in twelve modules an above-base vowel sign took a below-base anchor (Devanagari े on व sat on the baseline, Tamil ூ floated onto the next glyph, Khmer and Myanmar above marks were 630 units low); Extension (type 9) positioning lookups were skipped. Mark classes are now unique across subtables and a mark carries one anchor triple per subtable that covers it.
- **fix(shaping):** the Tamil shaper treated ி (U+0BBF) as a pre-base vowel sign and drew விலை as வெலை; the Devanagari and Bengali shapers emitted the reph before the base with a post-base offset formula, so प्रदर्शन lost its reph and समर्थन read समथन; the Telugu shaper never consulted GSUB, so ప్రదర్శన had no subjoined forms; Devanagari ो and ौ were split into two glyphs the font draws as one; a greedy ligature driver could not tell a `rphf` result from a `blwf` result of the same input pair. All five shapers now run on the Indic engine, and `tests/shaping/indic-real-font.test.ts` holds the words of the report on the bundled fonts.
- **fix(shaping):** Bengali and Tamil text had no language branch in `detectCharLang()`, so a multi-font document sent them to the first registered font that covered the code point.
- **fix(fonts):** `head.checkSumAdjustment` in every embedded subset is computed (`0xB1B0AFBA − Σ file`) instead of written as zero, as ISO/IEC 14496-22 §5.2.3 requires; rasterisers ignore the field, strict font validators do not.
- **fix(tools):** `compileFontData()`'s CommonJS output omitted the `features` and `kern` tables its ESM output carried.
- **fix(fonts):** COLRv1 sweep-angle bias; seven transform formats that sent their glyph to monochrome.
- **fix(core):** colour-emoji gradient layers whose stops share one colour and fade only in alpha (Noto's soft shadows and vignettes) were painted as a flat opaque disc, turning 👩, 👨, 🧑, 😊, 🌍, 🎂, 🏳️‍🌈 and about fifty other glyphs into silhouettes; such layers are omitted until luminosity soft masks land, and a single-colour gradient paints as its solid.
- **fix(core):** base-14 text is measured once, not encoded twice — the CP1252 marks (— … “ ” ‘ ’) and invisible bidi controls measured at the 556-unit default, so right- and centre-aligned lines containing them missed their margin and an opening quote hung too far.
- **fix(core):** a no-break space (U+00A0) or narrow no-break space (U+202F) reaches a registered font that has the glyph instead of being folded to an ordinary space, so `punctuationSpacing: 'fr'` is distinguishable from `'fr-CA'` and the character extracts as written.
- **fix(core):** `keepHeadingsWithNext` reserves the lines the paragraph splitter will actually place (`orphans`, and a table's trailer), so a heading is no longer stranded when `splitParagraphs` is on.
- **fix(core):** the PDF/X TrimBox synthesised for a page with a `bleedBox` and no `trimBox` is the BleedBox, not the MediaBox.
- **fix(core):** printer's marks keep at least `max(weight, 0.5)` pt clear of both the trim line and the sheet edge; at a 3 mm bleed the registration cross and the crop marks ended exactly on the TrimBox line and exactly on the MediaBox edge, so a viewer's page border or the guillotine took their outer half. Targets are re-centred and shrunk to fit, and dropped below a 6.6 pt strip rather than drawn clipped.
- **fix(fonts):** glyphs introduced by `fontFeatures` are embedded, listed in `/W` and mapped in ToUnicode; they rendered blank before.
- **fix(fonts):** embedded subsets keep the source font's `prep`, `fpgm`, `cvt ` and `gasp` tables (copied verbatim, never synthesised), so hinting rasterisers retain dropout control and grid-fitting: thin diagonals such as the lowercase `w` of Noto Sans no longer render greyish at small sizes. Outlines are byte-identical; the cost is 48 bytes for most bundled faces and at most 4.2 KB for the hinted Cyrillic, Math, Georgian, Armenian, Arabic, Hebrew and Tai Le faces.
- **fix(core):** justified text keeps its space glyphs and writes one `TJ` array per line.
- **fix(core):** an OutputIntent profile is checked for the ICC `acsp` signature and a size field within the buffer, in the writer (`layout.outputIntent`) and in `validatePdfX()`; a 200-byte buffer that merely spelt `CMYK` at byte 16 was accepted as a press profile before.
- **fix(samples):** sample output depended on the machine's locale — amounts were formatted with a bare `toLocaleString()`.
- **fix(parser):** the inline-dictionary skip in `extractText()` consumed the operator following `>>`.
- **fix(samples):** the typography showcase used straight apostrophes and quotes, stripped accents and breakable thousands separators, and two of its pairs were byte-identical files.
- **fix(fonts):** the GSUB single-substitution parser (offset, extension lookups, discretionary features) is locked by a synthetic-font test rather than by the publish-only font rebuild.

- **docs(meta):** roadmap moves six closed workstreams to Released and restates what remains; `AGENTS.md` condensed, `CLAUDE.md` added, `CONTRIBUTING.md` gains the release procedure; counts and versions are verified against `docs/assets/ecosystem.json` in every agent-facing file; documentation re-audited as of 2026-09-15.

## Upgrade

No public API was removed or renamed. Drop-in replacement for v1.7.0 for every program that does not rely on the four behaviours below, and output is byte-identical for existing inputs except where the previous output was wrong.

Four calls behave differently:

- **`setDeflateImpl()` validates the compressor it is given** and throws, at build time, when the function returns raw DEFLATE (RFC 1951) instead of zlib-wrapped data (RFC 1950) — the 1.7.0 documentation recommended `fflate`'s `deflateSync`, which is raw, and a document built with it was unreadable. Pass a zlib-producing function (`zlibSync`, `node:zlib` `deflateSync`), or a raw one to the new `setDeflateRawImpl()`. ([#78])
- **`parseColor()` accepts four values** as CMYK — a percent tuple or a four-operand string. `parseColor([0, 0, 0, 100])` and `parseColor('0 0 0 1')` both threw in 1.7.0 and return `'0 0 0 1'` now; code that relied on the throw to reject four-element input must check the length itself.
- **`extractText()` returns the `/ActualText` of a marked-content span** instead of the glyphs shown inside it. Text extracted from tagged pdfnative output, or from any tagged PDF, can therefore differ from 1.7.0 — it now matches what the writer declared.
- **The `{date}` header and footer placeholder follows `layout.creationDate`** (or the process-wide `setDefaultCreationDate()`) instead of the wall clock, so a pinned build renders the pinned date. A document that sets `creationDate` and uses `{date}` therefore changes bytes; one that sets neither does not. Dates are written in UTC (`D:20260101000000+00'00'`, `2026-01-01T00:00:00+00:00`), so the same instant yields the same bytes on every host; a build that relied on the host zone appearing in `/CreationDate` — a `+02'00'` offset, or a `{date}` that rolled over at local midnight — sees the UTC form instead.

One input is rejected that was accepted before: `layout.outputIntent.iccProfile` must carry the ICC `acsp` signature and a size field no larger than the buffer. Real profiles do; a hand-made stub that only spelt a colour space at byte 16 now throws at build time.

Deliberate output changes — each was wrong before, and each moved sample is re-anchored to 1.8.0 in `tests/regression/baselines/samples.sha256.json`:

- **Khmer and Myanmar text** — subscript consonants now use their subscript glyphs, a kinzi no longer takes horizontal space, and a second mark on one base sits on the first instead of over it.
- **Tai Tham and Cham text** set with a font you registered yourself is shaped by the Universal Shaping Engine; 1.7.0 bundled no font for either and took the plain per-codepoint path.
- **Colour-emoji flags** carry their shaded wave; glyphs built on COLRv1 transforms render in colour instead of monochrome.
- **Text using fonts whose single substitutions were mis-read** — notably CJK faces and Lao — now gets the glyphs the font specifies, and discretionary alternates (`aalt`, stylistic sets, small caps) no longer apply unasked.
- **Soft hyphens** no longer render mid-word, and lines containing no-break spaces measure correctly, so they can wrap differently.
- **A no-break space in text set with a registered font** (Noto Sans has the glyph) is emitted as U+00A0 and extracts as U+00A0; it was folded to an ordinary space before. Same advance in Noto Sans, so nothing moves — four `pdfa-latin` samples with `1 000`-style figures are re-anchored.
- **Right- and centre-aligned base-14 text containing — … “ ” ‘ ’ or an invisible bidi control** now lands on its margin; the estimate measured those characters at 556 units. `parser/text-extract-report` and `stress/table-micro-columns` are re-anchored.
- **`signature/digital-signature-info.pdf`** — the note inside the sample quotes Adobe Reader's English strings instead of the French ones; a sample-text change only, re-anchored to 1.8.0.
- **`alphabet/*.pdf` (27 plates)** — wider columns and neutral type labels; presentation of the sample only, no engine change; all re-anchored to 1.8.0.
- **Every document drawing `print.marks`** — crop marks and registration targets now stop 0.5 pt short of the trim line and the sheet edge; `print/print-bleed-marks`, `print-cmyk-pdfx4` (which also gains colour bars at a 5 mm bleed), `print-cmyk-pdfa2b` and `print-explicit-boxes` are re-anchored.
- **Colour emoji** whose COLRv1 artwork ends in an alpha-only gradient (about fifty glyphs, 👩 and 👨 among them) lose the opaque disc that hid their face and keep the artwork underneath; the soft shadow itself is not rendered until 1.9. `emoji/color-emoji-basic`, `color-emoji-sequences` and `color-emoji-skin-tones` are re-anchored.
- **Every PDF that embeds a TrueType subset** changes bytes twice over while its glyph outlines do not: the subset keeps the source's hinting tables (`prep`, `fpgm`, `cvt `, `gasp`) when the source carries them, and its `head.checkSumAdjustment` is computed instead of zero. Every such sample is re-anchored, the eight set in the Greek, Polish, Turkish and Vietnamese subsets included (those faces carry no hinting tables, but every subset has a checksum), and a downstream byte-comparison pipeline should expect the same.
- **Every script with mark positioning** — Arabic, Hebrew, Thai, Lao, Khmer, Myanmar, Tibetan, Devanagari, Bengali, Tamil, Telugu, Sinhala, Tai Tham, Cham, and Latin, Cyrillic or Greek text with anchored diacritics — takes its vowel signs, harakat, niqqud, tone marks and stacked marks from the anchor class the font designed for them. Above-base marks that sat on the baseline or on a below-base anchor move to their designed height; text that was already right keeps its position but its font module's data changed. Every alphabet plate, language document, shaping, extreme, bidi, diverse and financial sample set in those fonts is re-anchored.
- **Devanagari, Bengali, Tamil, Telugu and Sinhala text** is shaped by the Indic OpenType engine: the Tamil i-matra ி stays to the right of its consonant and only ெ ே ை (and the pre-base halves of ொ ோ ௌ) move left; the reph of प्रदर्शन, समर्थन or কর্ম sits over the consonant after the base, at zero advance; Telugu subjoined consonants and vattu appear (ప్ర, స్త్ర); conjuncts, half forms and rakar come from the font's own `akhn`, `half`, `cjct`, `blwf` and `vatu` features rather than from a flat ligature list; Devanagari ो and ौ are one glyph; a virama that no form absorbs stays visible. `hi`, `bn`, `ta`, `te`, `si` samples and every multi-script sample containing them are re-anchored.
- **Latin text with free-standing combining marks** set in a registered font that anchors them (Noto Sans) renders composed instead of as a base followed by a spacing mark; text without such marks, and text set in the base-14 fonts, is untouched.
- **ToUnicode CMaps** of documents whose shaper produced a conjunct, a subjoined form or a composed mark now map that glyph to its source code points as a multi-code-point `bfchar`; extraction of those clusters no longer yields U+FFFD in untagged output. The CMap stream changes bytes for every affected sample.
- **The twenty-nine language documents** (`doc-thai`, `doc-bengali`, `doc-tamil`, `doc-devanagari`, `doc-telugu`, `doc-sinhala`, `doc-tibetan`, `doc-khmer`, `doc-myanmar`, `doc-amharic`, `doc-arabic`, `doc-hebrew` and the four new African ones) are one-page conformance pages generated from a data table; their text changed by design.
- **Documents registering the Polish, Turkish or Vietnamese subsets** fall back to another registered font for characters those subsets cannot draw, instead of rendering blanks.
- **`inspectDocumentLayout()`** reports the same page count as the build when a table of contents is present.

Two options ship with a known limit, documented in the typography guide: `punctuationSpacing: 'fr'` needs a registered font to render its narrow no-break space (WinAnsi has none, so base-14 output degrades to `'fr-CA'`), and `fontFeatures: ['tnum']` or `['lnum']` change nothing with the bundled Noto Sans, whose figures are tabular and lining by default — the new `TYPOGRAPHY_FEATURE_INEFFECTIVE` diagnostic says so.

The Indic engine has known limits too, documented in the text-shaping rules: GSUB alternate (type 3) and reverse-chaining (type 8) lookups are not applied, a mark-filtering-set flag is treated as "skip no mark", pair kerning is not applied inside a shaped run, variable fonts are read at their default instance, and Gujarati, Gurmukhi, Kannada, Malayalam and Odia have no bundled font (a font you compile yourself with `compileFontData()` carries its `otl` tables, but no shaper is registered for those scripts yet).

## Downstream integration notes

For pdfnative-cli, pdfnative-mcp and pdfnative-react, which pin `^1.7.0` and therefore resolve to 1.8.0:

- **Type widening.** `PdfColor` now includes `PdfCmykTuple` and `PdfCmykString`, and `PdfDiagnosticCode` gains six codes (`PDFA_DEVICE_CMYK_CONTENT`, `PDFA_ICC_PROFILE_VERSION`, `PDFX_NO_FONT_ENTRIES`, `PDFX_DEVICE_CMYK`, `PDFX_ANNOTATIONS`, `TYPOGRAPHY_FEATURE_INEFFECTIVE`). Code that switches exhaustively over `PdfDiagnosticCode` with a `never` check will need the new cases; the union is additions-only by contract. The option types a wrapper re-exposes are all named exports now (`TypographyOptions`, `ColourBarOptions`, `PrinterMarksOptions`, `PrintOptions`, `CustomOutputIntent`).
- **New layout options** to expose: `typography` (including `hyphenationLanguage`), `pdfx`, and CMYK or Gray `outputIntent` profiles. `pdfx` and `tagged` are mutually exclusive and throw together. Two value shapes need schema work too: colour fields now accept a four-element CMYK tuple or a `'c m y k'` string (a hex-or-RGB schema, or a lint rule typed for RGB, rejects them), and `print.marks` accepts the object form `{ colourBars: true | { tints, size } }` beside `true`. `docs/data/surfaces.json` records which surface exposes what.
- **New error messages to classify.** The PDF/X coherence errors start with `PDF/X` or `layout.pdfx` (`layout.pdfx and layout.tagged cannot be combined`, `PDF/X forbids encryption`, `PDF/X-4 requires layout.outputIntent`, `PDF/X-4 requires an output (printer) profile`, `PDF/X requires the trapping state to be known`, `PDF/X pages carry a TrimBox or an ArtBox, not both`, `layout.pdfx: unknown target`); a CLI or server that maps `print.`, `chart:` and `outputIntent.` prefixes to an input-error code should add those two prefixes, or the errors surface as runtime failures. All of them, with the `outputIntent.` and `print.` messages, are served verbatim in `docs/data/errors.json` under `buildErrors`, so a classifier can be generated rather than hand-written.
- **Hand-enumerated surfaces to refresh.** pdfnative-cli's `--font` allow-list, its `--strict` help text and its schema descriptions enumerate the bundled scripts by hand (22 today); pdfnative-mcp's `lang` enum likewise. Adding `lo`, `nod`, `khb`, `tdd` and `cjm` is a change in those repositories, not a consequence of the engine bump.
- **`{date}` and `creationDate`.** A wrapper that exposes `creationDate` (pdfnative-mcp does on its nine document tools) now also pins the `{date}` placeholder, and every date is written in UTC, so a pinned build is byte-identical across hosts without a `TZ` pin; document that alongside the reproducible-output promise. A wrapper test that asserted a local-zone offset in `/CreationDate` needs `+00'00'`.
- **Four language keys, no new font.** `ha`, `yo`, `ig` and `sw` are sample labels over the bundled `latin` module; a CLI `--font latin` or an MCP `lang: 'latin'` already renders Hausa, Yoruba, Igbo and Swahili with their tone marks attached. A surface that maps language codes to modules can alias the four to `latin` rather than add entries.
- **Shaped-glyph provenance.** `ShapedGlyph` gains an optional `cps` (source code points); a consumer that constructs `ShapedGlyph` values by hand needs no change, one that re-implements ToUnicode generation can read it.
- **`FontData.otl`.** Optional on the type, so hand-built or 1.7.0-era font objects still register; a font compiled with 1.8.0's `compileFontData()` or shipped in `pdfnative/fonts/*` carries it. `markAnchors.marks[gid]` and `mark2Classes[gid]` are flat triples `[class, x, y, class, x, y, …]` (one per subtable) instead of a single `[x, y, class]`; code reading a bundled module's anchors directly must iterate.
- **New validator.** `validatePdfX()` sits beside `validatePdfUA()` for verify commands and tools. It reports errors 1.7.0 did not: fonts inside annotation appearances, OPI, PostScript and reference XObjects, embedded files, any `/TR` transfer function; a file that passed the 1.7.0 validator can fail the 1.8.0 one for one of those reasons.
- **`HyphenationProvider`** now receives `(word, lang?)`; a provider written against the one-argument shape keeps working.
- **Font modules** were regenerated: they carry `kern`, `features` and `otl` tables, corrected GSUB data, and mark anchors with one class per subtable. Consumers that vendor module files should refresh them. Sizes move with the anchors that were previously dropped and the layout tables that are new: Noto Sans 2 937 → 3 177 KB, Devanagari 917 → 1 043 KB, Tibetan 2 855 → 2 978 KB, Cyrillic 1 018 → 1 097 KB, Bengali 654 → 704 KB, Telugu 1 495 → 1 525 KB, Sinhala 1 657 → 1 669 KB; the other modules grow by 1–21 KB and the two emoji modules are unchanged.
- **Colour-emoji module** grows to 4 969 KB with skin tones.
- **Script count** is 27; surfaces that enumerate scripts should add Lao, Tai Tham, New Tai Lue, Tai Le and Cham (`lo`, `nod`, `khb`, `tdd`, `cjm`).
- **Bundle size.** The published `dist/index.js` tree-shakes per export; a tool that bundles pdfnative can drop its own workarounds for the previously retained crypto and shaping tables.
