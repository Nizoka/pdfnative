# pdfnative v1.8.0

<!-- GitHub Release title: v1.8.0 — typography, 27 scripts, CMYK & PDF/X-4 -->

_Released 2026-09-13_

The typography and print release. Long reports now typeset like documents rather than generated pages: paragraphs break across pages under widow and orphan rules, headings stay with what they introduce, body text justifies with hanging punctuation, and a registered font's pair kerning and OpenType figures apply on request. Five scripts of mainland South-East Asia join (27 in all), two of them shaped by a Universal Shaping Engine generated from the Unicode Character Database. Colour emoji gain every COLRv1 transform, variable paints and structural masks, so flags keep their shaded wave, and the bundled module carries skin tones. For print, colours can be CMYK, OutputIntents can be CMYK or Gray without breaking a PDF/A claim, printer's marks use the registration colour, and a document can claim PDF/X-4 and check itself with `validatePdfX()`. Underneath, every sample is deterministic and held byte for byte to the release that last changed it. **100% backward-compatible with v1.7.0** — 47 exports added and none removed; every new capability is a new API or an opt-in option, and existing inputs render byte-identically except where the previous output was wrong, each case listed under Upgrade. Zero runtime dependencies, 3214 tests across 150 files.

## Highlights

- **Typography** — `layout.typography` adds paragraph splitting with `widows` / `orphans`, `keepHeadingsWithNext`, `align: 'justify'` and `opticalMargins`, soft hyphens and a `setHyphenationProvider()` seam, ISO 80000-1 unit binding, punctuation-spacing presets and rules, exact base-14 metrics, pair `kerning`, and `fontFeatures` such as `tnum` for columns of figures. New [typography guide](../docs/guides/typography.md).
- **27 scripts and a Universal Shaping Engine** — Lao, Tai Tham, New Tai Lue, Tai Le and Cham, with the engine's categories derived from UCD 17.0.0 and one shaper registry in place of three dispatch ladders. Khmer subscripts, Myanmar kinzi and stacked marks render correctly.
- **Colour emoji** — COLRv1 transforms (formats 12–31), variable paints at the default instance, `SRC_IN` / `DEST_IN` masks as clipping paths; 150 bundled skin-tone forms.
- **CMYK and PDF/X-4** — `[c, m, y, k]` colours, CMYK and Gray OutputIntents with RGB content kept conforming through a calibrated `/DefaultRGB` (veraPDF-validated under PDF/A-1b and 2b), registration-colour marks, `pdfx: 'pdfx4'`, and `validatePdfX()`. See the [print guide](../docs/guides/print.md).
- **Regression harness** — `npm run verify:samples` holds all 270 samples to the bytes of the release that last changed them, blocking in CI.

- **feat(shaping):** Lao (`shapeLaoText()`, `buildLaoClusters()`), Tai Tham, New Tai Lue, Tai Le and Cham with their detection predicates and font modules; the Universal Shaping Engine (`useCategory()`, `useCategories()`, `splitUseSyllables()`, `reorderUseCluster()`, `shapeUseText()`, `USE_UNICODE_VERSION`); `SCRIPT_SHAPERS` and `findShaper()`; `npm run verify:unicode`.
- **feat(fonts):** COLRv1 transform, variable and mask paints; build-time clip compaction; `ClipOutline`; 150 bundled skin-tone sequences and the CLI `--sequences skin` preset; `npm run verify:fonts`, which rebuilds every font module from its declared source and compares byte for byte.
- **feat(core):** CMYK colours (`PdfCmykTuple`, `PdfCmykString`, `PdfColorSpace`, `ResolvedColor`, `resolveColor()`, `fillOp()`, `strokeOp()`); CMYK and Gray OutputIntents; `PDFA_DEVICE_CMYK_CONTENT`; `pdfx: 'pdfx4'` with `PDF_X_CONFORMANCE_TARGETS`, `PdfXConformanceTarget` and the `PDFX_NO_FONT_ENTRIES`, `PDFX_DEVICE_CMYK`, `PDFX_ANNOTATIONS` diagnostics; registration-colour printer's marks; `setDeflateRawImpl()` and `wrapZlib()`.
- **feat(parser):** `validatePdfX()` and `PdfXValidationResult`.
- **feat(samples):** 28 new samples (270 in all) and two executable recipes, `typography-report` and `print-pdfx4`.

## Changed

- **refactor(core):** one pagination planner for the builder and `inspectDocumentLayout()`; one colour-operator choke point for 101 call sites.
- **refactor(shaping):** one shaper registry; the hand-written fall-through that shaped any unmatched run as Devanagari is gone.
- **perf(fonts):** pair kerning stored in OpenType class form — 46 KB for Noto Sans instead of 594 KB expanded, so modules keep their pre-kerning size and parse time.
- **feat(core):** `parseColor()` also accepts CMYK inputs; `outputIntent` also accepts CMYK and Gray profiles and is resolved before any byte is written.
- **chore(deps):** `js-yaml` pinned to 4.3.2 through `overrides` (GHSA-2883-xcg3-v3hh, reached only through ESLint).

## Fixed

- **fix(core):** AcroForm `/DR` font embedded under a PDF/A claim, so interactive forms can be archival ([#74]).
- **fix(core):** `inspectDocumentLayout()` reported fewer pages than the build for documents with a table of contents ([#75]).
- **fix(core):** `setDeflateImpl()` documentation recommended implementations that produce unreadable streams; injected compressors are now validated ([#78]).
- **fix(core):** soft hyphens rendered as visible hyphens; no-break spaces measured about twice their width.
- **fix(fonts):** GSUB single substitutions read from the wrong offset, missed extension lookups and merged discretionary features; font modules advertised glyphs a subsetted face could not draw.
- **fix(shaping):** Khmer subscripts, Myanmar kinzi and stacked marks; U+061C ARABIC LETTER MARK stripped before measuring.
- **fix(fonts):** COLRv1 sweep-angle bias; seven transform formats that sent their glyph to monochrome.

## Upgrade

No breaking changes. Drop-in replacement for v1.7.0. Output is byte-identical for existing inputs, with these deliberate exceptions — each was wrong before:

- **Khmer and Myanmar text** — subscript consonants now use their subscript glyphs, a kinzi no longer takes horizontal space, and a second mark on one base sits on the first instead of over it.
- **Colour-emoji flags** carry their shaded wave; glyphs built on COLRv1 transforms render in colour instead of monochrome.
- **Text using fonts whose single substitutions were mis-read** — notably CJK faces and Lao — now gets the glyphs the font specifies, and discretionary alternates (`aalt`, stylistic sets, small caps) no longer apply unasked.
- **Soft hyphens** no longer render mid-word, and lines containing no-break spaces measure correctly, so they can wrap differently.
- **Documents registering the Polish, Turkish or Vietnamese subsets** fall back to another registered font for characters those subsets cannot draw, instead of rendering blanks.
- **`inspectDocumentLayout()`** reports the same page count as the build when a table of contents is present.

## Downstream integration notes

For pdfnative-cli, pdfnative-mcp and pdfnative-react, which pin `^1.7.0` and therefore resolve to 1.8.0:

- **Type widening.** `PdfColor` now includes `PdfCmykTuple` and `PdfCmykString`, and `PdfDiagnosticCode` gains four codes. Code that switches exhaustively over `PdfDiagnosticCode` with a `never` check will need the new cases; the union is additions-only by contract.
- **New layout options** to expose: `typography`, `pdfx`, and CMYK or Gray `outputIntent` profiles. `pdfx` and `tagged` are mutually exclusive and throw together.
- **New validator.** `validatePdfX()` sits beside `validatePdfUA()` for verify commands and tools.
- **Font modules** were regenerated: they carry `kern` and `features` tables and corrected GSUB data. Consumers that vendor module files should refresh them.
- **Colour-emoji module** grows to 4 969 KB with skin tones.
- **Script count** is 27; surfaces that enumerate scripts should add Lao, Tai Tham, New Tai Lue, Tai Le and Cham (`lo`, `nod`, `khb`, `tdd`, `cjm`).
