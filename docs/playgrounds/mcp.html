pdfnative-mcp tool explorer

The tools an AI assistant gets when you wire pdfnative-mcp v1.8.0 (pins pdfnative ^1.9.0, requires pdfnative ≥ 1.9.0 and Node ≥ 22; _meta.apiVersion = TOOL_API_VERSION 1.8.0; built on @modelcontextprotocol/server ^2.4.0, so a modern HTTP request that omits the MCP-Protocol-Version header is answered 400 / -32020) into Claude Desktop, Cursor, Continue, Zed, or any other MCP client (Cline, Windsurf, Goose, Gemini CLI…). The server exposes 28 tools — the catalogue did not grow in v1.8.0; what each tool can do did.

New in v1.8.0:

  • Spot colours — print.spotColours declares up to 32 inks with a CMYK or RGB alternate; { spot, tint } paints a /Separation, { inks } a /DeviceN mix, at the colour inputs of the nine document tools (not on outline entries, which the engine keeps process RGB, nor on annotate_pdf) — an undeclared ink is refused by name as VALIDATION_ERROR.
  • A base text direction (auto / ltr / rtl, per paragraph too) with /ActualText on untagged right-to-left runs (actualText, default true) so extract_text reads logical order.
  • The PDF/A-2 + PDF/X-4 dual claim — pdfx: "pdfx4" with pdfA: "pdfa2b" or "pdfa2u" in one file.
  • JPEG 2000 images (mimeType: "image/jp2", passed through as /JPXDecode).
  • Link annotations on existing PDFs (annotate_pdf type: "link") and one colour per bar (add_chart series[].colors).
  • 32 scripts in add_international_text — Gujarati, Gurmukhi, Kannada, Malayalam and Odia join: 39 lang values with latin / emoji / math and the four Latin aliases.
  • An explicit extract_text onStreamError policy, and offline LTV material with match on add_ltv.
  • An operator font sandbox (PDFNATIVE_MCP_FONT_DIR → font: "<slug>" on three tools), public result URLs (PDFNATIVE_MCP_OUTPUT_BASE_URL) and two always-listed governance resources.

Still there from earlier releases: the v1.7.0 typography option, CMYK colours and PDF/X-4 output with its structural check in validate_pdf { standard: "pdf-x-4" }, reproducible output (every date written in UTC; a per-call creationDate or the operator pin PDFNATIVE_MCP_CREATION_DATE / SOURCE_DATE_EPOCH), the v1.6.0 PAdES ladder add_ltv / timestamp_pdf (with RFC 3161 timestamps on sign_pdf), update_metadata, the read-only inspect_layout pagination preview, all 13 block kinds in generate_basic_pdf, print production and charts v2, the v1.5.0 add_chart / form / encryption tools, the v1.4.0 markup annotate_pdf and network-free draft_governance_issue, the v1.3.0 page-tree trio merge_pdfs / split_pdf / extract_pages, a pdfA flag on every document tool, multi-script lang, and token-frugal read modes (verbosity / fields).

Each card below shows a real example prompt, the payload it runs, and a button that produces the very PDF (or report) the AI assistant would receive — simulated with the pdfnative engine in your browser; the server returns the same shape. Older cards show the pdfnative library payload this page executes (the MCP schemas differ — see the MCP guide); the v1.7.0 and v1.8.0 cards show the exact MCP tool-call payload and map it to the engine in front of you. No API keys, no install, no LLM cost.

For the full integration story (config, security model, signed-document workflow), see the MCP guide.

1. Configure your client

Pick your client. The snippet below is what you paste into its MCP servers config. npx downloads pdfnative-mcp on first use; no global install needed.

Other clients: any tool that speaks the Model Context Protocol over stdio works — Cline, Windsurf, Goose, Aider, LibreChat, Sourcegraph Cody, Gemini CLI, and your own custom client. Use the same command: "npx" / args: ["-y", "pdfnative-mcp"] pair in whatever JSON shape your client expects.

2. Operator environment — the 14 variables

Everything the server reads from its process environment, as declared in server.json (MCP registry schema 2025-12-11). All are optional; none is ever settable from a tool argument. Set them in the env block of your client config. The two tagged v1.8.0 are new in this release; the two tagged v1.7.0 arrived with the previous one.

VariablePurpose
PDFNATIVE_MCP_OUTPUT_DIRAbsolute path of a sandboxed directory where outputMode: "file" may write PDFs. Unset: every tool returns base64 only.
PDFNATIVE_MCP_OUTPUT_BASE_URL v1.8.0Public base URL of the output directory when the operator serves it over HTTP (e.g. https://files.example.com/pdf/): every file-mode result then carries url (base + sandbox-relative path, percent-encoded) and names it instead of the host path. Absolute http(s) URL with no credentials, query or fragment; a trailing slash is added; requires PDFNATIVE_MCP_OUTPUT_DIR (set both or neither); an invalid value refuses to start. The server never requests that URL.
PDFNATIVE_MCP_CACHE_DIROpt-in content-addressed response cache (SHA-256 keyed, 1 h TTL, 256 MiB LRU, plaintext at rest). Never caches encrypt / decrypt, sign, timestamp, add_ltv, update_metadata, encrypted builds, file output or any call carrying password / encrypt. The namespace carries the creation-date pin below and the font-sandbox fingerprint.
PDFNATIVE_MCP_FONT_DIR v1.8.0Operator font sandbox: absolute path of an existing directory holding 1–64 .ttf / .otf files (16 MiB each). At boot every file is parsed by the engine's own font compiler and registered as custom:<slug>, the slug being the file name folded to lower-case [a-z0-9-] (≤ 64 characters, e.g. Brand Sans-Bold.ttf → brand-sans-bold); two files folding to one slug, a file that is not a font, or no font at all refuse to start. Tools name a face with font: "<slug>" (generate_basic_pdf, add_international_text, inspect_layout); an unknown slug is FONT_NOT_FOUND listing the registered ones. Never a path from a tool argument; paths are never echoed.
PDFNATIVE_MCP_PORTServe Streamable HTTP on this loopback port instead of stdio (stateless). Unauthenticated unless the token below is set.
PDFNATIVE_MCP_HTTP_TOKENSecret. Bearer token for the HTTP transport (≥ 16 chars, no whitespace); /mcp answers 401 without it. Never logged.
PDFNATIVE_MCP_MAX_INFLATE_BYTESPer-stream FlateDecode decompression cap in bytes (zip-bomb mitigation; default 104857600 = 100 MiB). Integer ≥ 1024; an invalid value refuses to start.
PDFNATIVE_MCP_CREATION_DATE v1.7.0ISO 8601 instant with a time zone (e.g. 2026-01-01T00:00:00Z) pinned as the creation date of every generated document — reproducible bytes on any host. An invalid value refuses to start.
SOURCE_DATE_EPOCH v1.7.0The reproducible-builds.org convention: integer seconds since the Unix epoch, used as the pin when PDFNATIVE_MCP_CREATION_DATE is unset. A shell that already exports it pins every document. An invalid value refuses to start.
PDFNATIVE_MCP_TSA_URLhttp(s) URL of the RFC 3161 timestamp authority used by sign_pdf timestamp: true and timestamp_pdf (PAdES B-T / B-LTA). Unset: those calls fail with TSA_NOT_CONFIGURED and no request is made.
PDFNATIVE_MCP_TSA_AUTHSecret. Optional Authorization header value sent to the TSA (Basic … or Bearer …). Never logged or echoed.
PDFNATIVE_MCP_REVOCATIONocsp, crl or ocsp,crl: enables online revocation collection for add_ltv mode: "online" (PAdES B-LT). Unset: that mode fails with REVOCATION_NOT_CONFIGURED; mode: "offline" stays offline.
PDFNATIVE_MCP_NETWORK_ALLOWED_HOSTSComma-separated allow-list of OCSP / CRL responder hosts (host, host:port or *.suffix). Mandatory when the revocation variable is set; http(s) only, no credentials, no redirects, internal addresses rejected unless listed verbatim.
PDFNATIVE_MCP_NETWORK_TIMEOUT_MSPer-request timeout for TSA / OCSP / CRL calls in milliseconds, 1000–120000 (default 10000).

Creation-date precedence: per-call creationDate → PDFNATIVE_MCP_CREATION_DATE → SOURCE_DATE_EPOCH → the wall clock. The pin is read once at boot and its source is logged on stderr; a call's own creationDate always wins. Not covered by any pin, by design: signingTime, modDate, RFC 3161 tokens and revocation data, encryption (fresh key, salts, IVs), ECDSA signatures.

3. Prompts and error codes

The server advertises the prompts capability with 7 prompts — read-only recipes an agent can load before it calls a tool. The catalogue is unchanged in v1.8.0 (no prompt was added); print_ready now covers spot inks and the dual claim, and the server instructions (about 8.4 kB of a 10 KiB budget) carry the decision tree for direction, font, link annotations and onStreamError:

  • governance_contract
  • draft_issue_workflow
  • pades_ladder
  • print_ready
  • reproducible_output
  • typography
  • pdfa_valid

Error codes — 48 in v1.8.0. One code is new: FONT_NOT_FOUND v1.8.0, returned when font names a slug the operator did not register (the message lists the registered slugs, or says that PDFNATIVE_MCP_FONT_DIR is unset). With strict: true the server escalates the first engine diagnostic to a stable code chosen from the diagnostic's own code (src/diagnostics.ts, escalate()): PDFA_* (now including PDFA1_JPX_IMAGE, PDFA_JPX_IMAGE and PDFA_GLYPH_WITHOUT_UNICODE) → PDF_A_COMPLIANCE_VIOLATION; PDFX_* (PDFX_NO_FONT_ENTRIES, PDFX_DEVICE_CMYK, PDFX_ANNOTATIONS) → PDF_X_COMPLIANCE_VIOLATION; anything else (TYPOGRAPHY_FEATURE_INEFFECTIVE, TEXT_GLYPH_NOT_COVERED) → DIAGNOSTIC_ESCALATED, whose message starts with [CODE]. Those three codes can only be returned by a call that sets strict: true; includeDiagnostics: true echoes the diagnostics without failing. Other codes you will meet on this page: VALIDATION_ERROR (an incoherent PDF/X request, a spot ink painted without a print.spotColours declaration, a link url outside http / https / mailto — all refused before any bytes exist), CHART_ERROR (a series[].colors array whose length differs from values), PRINT_ERROR (a file that is not an ICC profile), ENCRYPTED_SOURCE, GOVERNANCE_VIOLATION, PDF_PARSE_FAILED (also a content stream over PDFNATIVE_MCP_MAX_INFLATE_BYTES under the default onStreamError: "limit"). The PDF/X-4 card below prints the engine code and the server code it maps to whenever the build raises a PDFX_* diagnostic.

4. Resources

The server advertises the resources capability. resources/list always returns the two governance entries v1.8.0 — sandbox or not — so an agent on a remote host reads the same human-in-the-loop contract the governance_contract prompt summarises, byte-identical to the repository files:

  • pdfnative://governance/policy — application/json, .github/ai-governance.json verbatim
  • pdfnative://governance/rules — text/markdown, .github/AGENT_RULES.md verbatim

When PDFNATIVE_MCP_OUTPUT_DIR is set, every PDF a tool writes there is listed after them as pdfnative://output/<relative-path> (application/pdf, up to 1000 entries, 8 directory levels, 50 MiB per read), resources/templates/list advertises the address space pdfnative://output/{+path} (RFC 6570 reserved expansion — empty when file output is disabled), and PDF-producing tools attach a resource_link to the file they just wrote. resources/read re-validates every path against the sandbox (no traversal, .pdf only); an unknown URI is the protocol's resource-not-found error (-32602). The server keeps no registry: the list is the live content of the directory.

5. Try the tools

Loading pdfnative from esm.sh… this happens once per page load.

The interactive cards below cover the core document-authoring tools, the v1.3.0 page-tree trio (merge_pdfs, split_pdf, extract_pages), the v1.4.0 annotate_pdf, the v1.6.0 update_metadata, the five v1.7.0 cards (typography, PDF/X-4 with CMYK colours and colour bars, validate_pdf { standard: "pdf-x-4" }, inspect_pdf { check: ["pdfx", "trapped"] }, a reproducible build hashed twice) and the ten v1.8.0 cards — generate_basic_pdf with spot colours (plus an undeclared-ink refusal), add_international_text with direction: "auto" and its /ActualText spans (plus actualText: false), the PDF/A-2b + PDF/X-4 dual claim, embed_image with a JPEG 2000 file, annotate_pdf type: "link", add_chart with one colour per bar (plus a length-mismatch refusal), the five Indic scripts of pdfnative 1.9.0 as PDF/A-2u, extract_text with an explicit onStreamError, and two show-only cards for add_ltv offline material and the operator font sandbox — all the runnable ones build their own source PDFs in the browser and run the real pdfnative 1.9.0 API. Cards that produce no PDF by design: inspect_layout returns a pagination report, validate_pdf, inspect_pdf (PDF/X) and extract_text return structured reports (run them to see the JSON), and draft_governance_issue validates a report locally, network-free — use its Copy args button. The two show-only cards (add_ltv needs a signed PDF and DER material, the font input needs an operator-registered face) carry the exact arguments and their rules; copy them into your own client. Eight of the 28 tools have no card here: seven need a real PDF as input and run best from your own MCP client (verify_pdf, add_attachment, extract_attachments, read_form_fields, fill_form, encrypt_pdf, decrypt_pdf), and timestamp_pdf needs the operator-configured RFC 3161 authority a browser page cannot supply (PDFNATIVE_MCP_TSA_URL above). See the MCP guide for their full schemas.

6. Now ask your AI assistant

Once you've pasted the config snippet above and restarted your client, ask it anything PDF-shaped:

  • "Generate a 3-page invoice for ACME Corp totalling €1 200 and embed a QR code that links to the payment portal."
  • "Create a Thai-language welcome letter with our logo as a header."
  • "Draft a contract with a signature placeholder and inspect the resulting PDF for me."
  • "Set this report in justified text with widows and orphans of 3, then produce a PDF/X-4 version for the printer and validate it."
  • "Lay out this Arabic–English notice right-to-left where it should be, paint the header rule in our Pantone brand blue, and hand the printer a PDF/X-4 that is also archived as PDF/A-2b."

The AI assistant will pick the right tools, fill the JSON arguments, and pdfnative will render the PDF — no code from you.
